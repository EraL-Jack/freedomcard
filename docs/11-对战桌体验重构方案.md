# 11 · 对战桌体验重构方案（v0.1 建议稿）

> 触发：Era 2026-10-18 实机反馈四点 —— ①不像卡牌游戏 ②提示不明显、过阶段反馈差
> ③卡牌效果无法查看 ④攻击逻辑存在问题。
> 性质：**建议稿**。凡涉玩法/视觉决策的条目均标 `[待拍板]`，不擅自定稿。

---

## 1. 问题归因（先分清「缺输入」还是「没做好」）

| # | Era 的反馈 | 根因 | 归属层 | 是否缺 Era 输入 |
| --- | --- | --- | --- | --- |
| 1 | 不像卡牌游戏 | B6（配色/参考）与 B7（美术）一直「待输入」，占位渲染停留在最抽象的灰格子 | 客户端表现层 | 部分缺（B6/B7），但**结构化占位升级**不需要等 |
| 2 | 提示不明显、过阶段反馈差 | **B4 关键反馈 Era 早已填完**（攻击浮起撞击 / 受伤 -xx / 死亡爆炸 / 回合切换文字+音效），我方以「音效素材未给（B7-3）」为由把**整个 B4 含纯视觉部分一起搁置** —— 执行失误 | 客户端表现层 | **不缺**，视觉反馈即刻可做；仅音效等素材 |
| 3 | 卡牌效果无法查看 | 卡面只渲染 name/cost/power/kind，`text` 只在 `title` 悬停提示里（移动端等于没有）；没有详情查看入口 | 客户端表现层 | **不缺**（Era 的 5 张样例卡 text 已转录入卡池） |
| 4 | 攻击逻辑存在问题 | 待 Era 指认具体场景。候选分析见 §5 | 可能涉及规则层 | **缺**（需 Era 描述「什么操作 → 看到什么 → 期望什么」） |

**结论**：问题 1/2/3 全部是客户端表现层的事，且大部分不依赖新输入；问题 4 需要 Era 给出现象。

## 2. 重构边界（「完全重构」重构什么、不重构什么）

**不动**：`packages/core`（9 条规则、131 单测）、`packages/server`（房间/会话/计时）、
`packages/shared`（协议/卡池）、全部 E2E。理由：这些经测试与 Era 的规则输入双重确认，
重构它们只会引入回归，不解决 Era 提出的任何一点。

**重写**：`packages/client` 的对战桌相关组件（TableScreen / CardTile 及新增组件，约 12 个文件中的 4–6 个）。
客户端本来就薄（只发 Intent + reduce 渲染），重写表现层不影响架构铁律。

**B2 六排布局框架保留**（Era 填过且两次补正过），重构的是**框架内的视觉与交互质量**。

## 3. 工作包 P1 —— 卡牌与桌面视觉（对应反馈 ①）

| 项 | 现状 | 方案 |
| --- | --- | --- |
| 卡牌形态 | 64px 窄条文字按钮 | 标准卡比例（约 5:7）圆角卡框；左上**费用水晶**（圆形徽章）、右下**力量徽章**（剑形/圆形）、类型色条；中场留插图位（B7-1 素材到位前用类型色块+图标占位） |
| 状态语言 | 选中只有一圈细环 | 休眠=卡牌**横置 90°**（卡牌游戏通用语言）+ 降饱和；选中=上浮 + 描边加粗；可攻击=呼吸描边 |
| 区域造型 | 所有区域一模一样的灰框 | 卡组/墓地/除外=**一叠牌**的侧影 + 数量角标；费用区=竖置条带直接显示 n/上限；指挥官=圆形头像位 + 血量徽章（保留 X-11 位置） |
| 桌面氛围 | 灰底网格 | 深色桌面 + 中线分隔双方半场；我方半场在「你的回合」时边缘提亮 |
| 手牌 | 一行窄条 | 尺寸加大到可读，横向溢出滑动（B2-2）；点选后卡上浮并**在卡的周围**出操作按钮（出牌/充能/详情），遵守 B3-2「不要弹窗」 |

配色暂用「深桌面 + 琥珀金/青」中性方案占位，`[待拍板]` B6-1/B6-2 到位后整体换肤
（配色走 CSS 变量，换肤不动结构）。

## 4. 工作包 P2 —— 反馈系统（对应反馈 ②，落地 Era 已填的 B4）

| B4 条目 | 方案（视觉先行，音效留 B7-3 素材钩子） |
| --- | --- |
| 过阶段（Era 点名最差） | 顶部**阶段进度条**常显（抽牌→重置→充能→出牌→战斗→结束，当前段高亮）；每次推进全屏**横幅扫过**（大字「战斗阶段」，约 1s 淡出） |
| 回合切换 | 横幅「你的回合 / 对手回合」+ 我方半场边缘提亮（B4 原填「文字、音效」） |
| 攻击 | 攻击方卡牌**浮起并向目标位移撞击**后弹回（CSS transform，B4 原填「卡牌浮起来撞击对面」） |
| 受伤 | 指挥官头像抖动 + 红色 **-N 飘字**上飘消散（B4 原填「文字-xx」） |
| 单位死亡 | 卡牌碎裂/淡出动画（CSS 粒子或缩放淡出，B4 原填「爆炸」） |
| 服务端拒绝 | notice 从底栏一行小字改为**中央 toast**（大字号、3s 自动消失、可点掉） |
| 日志 | 保留右列（B2-5），但关键事件（破坏/掉血/胜负）彩色高亮、字号上调 |

实现全部基于 CSS transition/animation，**不引入 PixiJS**（素材与特效量级未到，避免无谓体积）。

## 5. 工作包 P3 —— 卡牌详情查看（对应反馈 ③）

- 任何可见卡（我方手牌/场上、对方场上、墓地展开后）提供**详情入口**：
  桌面端 hover 放大预览；移动端（B5-3 单指）点卡上浮后，卡周围按钮含「详情」（与出牌/充能并列，仍非弹窗式确认，符合 B3-2 的约束范围——该条约束的是**出牌确认**，详情查看是否同样禁弹层 `[待拍板]`）。
- 详情内容：大卡面 + **完整效果文本**（卡池 `text` 已在，Era 的 5 张样例卡原文已转录）
  + 关键词注释（嘲讽等）+ 当前力量值（含指挥官档位来源说明）。
- 占位卡 8 张无 `text`（ADR-0018 纪律：不写效果），详情里明示「占位卡，正式卡表待替换」。

## 6. 工作包 P4 —— 攻击交互引导（对应反馈 ④ 的 UX 面；规则面待指认）

UX 层（**无需新输入**，直接做）：
1. 点选攻击方后：合法目标**全部亮绿框**（对方随从 + 指挥官，嘲讽随从在场时只亮嘲讽）；
2. 攻击方与目标之间画**引导箭头**；点空白或再点攻击方取消（B3-4）；
3. 非法操作**本地拦截**：未休眠、当前阶段为战斗、轮到我 —— 不满足时按钮/卡牌直接不可点
   并附一句原因（不发请求等服务器打回，沿用 D-108 原则）；
4. 结算呈现：双方力量值对比数字先亮出（如 2 ⚔ 1），再播破坏/扣血结果。

规则层（**待 Era 指认**）。现行规则全部是 Era 确认过的，原样列出供对照：

| 规则 | 出处 | 可能导致「感觉不对」的点 |
| --- | --- | --- |
| 纯力量对比三分支：大者胜、等则双亡 | X-3 | 攻击方力量小则**自己**破坏 —— 「我打他，我没了」若无清晰呈现，体感像 bug |
| 打指挥官：防守方输则扣伤害值（默认 1） | X-4 / X-5 | 指挥官前期力量 0（曲线第 0 档，X-7），**任何随从打脸必胜必扣血**，指挥官不能反击 |
| 每单位每回合限攻击 1 次，攻击后休眠 | A9-2 | 休眠无视觉区分（现状仅一行小字）→ 「点不动了」像卡死 |
| 先攻方第一回合不可攻击 | A10-3 | 点了才被拒，提示在底栏角落 |
