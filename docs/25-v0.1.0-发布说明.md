## 1. 一句话

浏览器打开就能两个人实时对打的卡牌 Demo：把房间码给对方，或者一个人开人机局。
服务端权威、客户端只负责渲染，一局打完能在**同一间房**直接「再来一局」。

这不是「功能齐全的卡牌游戏」，是**规则与联机骨架跑通的第一版**：45 张卡的卡池、完整的一局流程、
BO1 / BO3 赛制、两个人真的能同时玩。美术、账号、观战、匹配都在 `docs/22` 的「第一版不做」里。

## 2. 这个版本能玩到什么

| 能力 | 说明 |
| --- | --- |
| **建房 / 加入** | 房主建房拿到 4 位房间码，对手输码加入；两边各自选卡组与指挥官 |
| **实时联机** | 服务端权威：客户端只发 `Intent`，服务端校验后广播事件与状态哈希，客户端不推算 |
| **人机对战** | 一个人也能开局自测；对手用哪套卡组可在首页下拉里指定（默认「电脑」随机） |
| **卡组编辑** | 一套 = **30 张主卡 + 1 位指挥官**；同名 ≤ 3；多套卡组存本机；首次进入预置三套基础卡组 |
| **卡池** | 47 个卡牌定义 = 45 张主卡（炎刃 / 霜律 / 星轨各 15）+ 2 张衍生物；**不限体系，随便混搭** |
| **对局流程** | 换牌 → 充能 → 出牌 → 战斗 → 结束回合；8 血、先手 5 张 / 后手 6 张 |
| **赛制** | BO1 / BO3；第 2 局换先手，**第 3 局由上一局败者先攻**（判和回落掷骰） |
| **再来一局** | 结算面板直接重开，**不换房间号**，对手不用重新加入 |
| **认输 / 离开** | 认输只判负本局（两段式确认防误触）；「离开」判负整个系列赛 |
| **断线重连** | 60 秒宽限内回来能接着打 |
| **移动端** | 手机竖屏自适应；横屏收成竖屏比例居中 |
| **战报** | 右侧战报记录「谁做了什么」，机制行默认收起（可展开）——回放入口置灰期间，这是唯一复盘手段 |
| **新手引导** | 首次进入 4 步浮层（换牌 → 充能 → 推进阶段 → 出牌），只出现一次 |
| **音效** | 打击 / 抽牌 / 结算三条，Web Audio 现场合成，零素材依赖，可静音 |

规则条文见 `docs/16`（8 血版），卡面文本规范见 `docs/18`，星轨与展示流程见 `docs/17`。

## 3. 怎么开始（30 秒）

**两个人玩**

1. 两人各自打开 `http://frp-cup.com:57732`，填昵称。
2. A 点「建房」→ 复制 4 位房间码发给 B。
3. B 点「加入」→ 输房间码 → 双方选卡组 → 都点「准备」→ 开局。

**一个人玩**

首页点「人机对战」直接进准备页，准备即开局。想指定对手卡组就用按钮左边的下拉。

> 两个窗口开在同一台电脑也可以，但请用**一个普通窗口 + 一个无痕窗口**（或两台设备）——
> 同一浏览器同一 `localStorage` 会共用昵称与卡组。

## 4. 规则速览（够打第一局）

| 项 | 口径 |
| --- | --- |
| 胜负 | 血量 8，先归零者负；40 轮后血量高者胜，同血量进即死模式 |
| 起手 | 先手 5 张、后手 6 张；双方各有一次换牌窗口（最多 3 张） |
| 充能 | 每回合可把手牌放进充能区换费用；先手首回合不抽不充能，之后每回合充能 2 |
| 费用上限 | 按累计充能次数取 1 / 3 / 5 / 10 |
| 打脸伤害 | 按力量分档 1 / 2 / 3，**无门槛** |
| 战斗 | 纯力量三分支：攻 > 守 守方破坏；攻 < 守 攻方破坏；相等双死。**随从没有生命值** |
| 指挥官 | 无力量值，每战斗阶段可攻击一次，基础伤害 1（可被本回合伤害加成提升），技能固定 2 费 |
| 冻结 | 只能选**未冻结**单位；对已冻结单位再冻结是空操作（缚锁者是卡面例外） |
| 霜痕 / 星轨 | 冻结敌方 +1 霜痕；展示 1 张 +1 星轨，都是永久计数，裁决官按层数分档 |

## 6. 已知限制（发布时确实存在）

按「会不会挡住打完一局」排序，前四条是**玩家会真的碰到**的：

1. **卡图与特效是纯色占位** —— 卡面只有底色 + 文字；音效是程序化合成的占位。等 `docs/19` 的 X-14 / X-15 拍板。
2. **没有账号** —— 昵称、卡组、引导状态全在本机 `localStorage`；换浏览器等于换身份，进度不跟人走。
3. **服务端重启即丢局** —— 房间与系列赛比分都在内存；重启后回放文件还在，但房间不重建。
4. **回放看不了** —— 记录一直在写（`app/replays/`，保留 7 天 / 500 MB），但观看入口置灰：公网走隧道、月流量有限。
   要开放只改 `client/src/features.ts` 的 `REPLAY_VIEW_ENABLED` 再 `pnpm build`。
5. **移动端只做了视口验证** —— 375 / 768 / 1440 三档渲染 + 390×844 的日志抽屉有 E2E；触摸拖拽与安全区未真机实测。
6. **准备后不能改卡组**，BO3 局间也不能换 —— 这是故意的（换卡组等于改赛制）。
7. **即死模式没有兜底计时**（H50）：理论上双方都打不出伤害时可无限拖，目前靠认输收尾。
8. **限流阈值是经验值**（建房 10 次/分、Intent 20 次/秒），未在真实多人负载下校准。
9. **隧道部署下限流按 IP 会失效** —— 所有公网客户端看起来都是 `127.0.0.1`，实际生效的是「按连接 + 全局」那一层。
10. 观感项：390px 下五区一行时区名偏窄、随从区空位占高偏多 —— 属于 X-14 视觉决策，等拍板。

完整 25 条范围约束见 `docs/22`；工程侧 35 条细节见 `app/README-运行说明.md §10`。

## 7. 这个版本**不做**什么

`docs/22-第一版不做清单.md` 是范围判据，原文一句话：**不做它，两个人能不能顺畅打完一局？**

能打完就进清单。目前 25 条，主要包括：响应窗口与对手回合出牌（N-01）、3 人以上（N-02）、
备牌与局间换卡（N-03）、卡牌收集养成（N-04）、伤害类型（N-05）、账号（N-08）、好友私聊（N-09）、
观战（N-10）、房间列表 / 匹配 / 天梯（N-11）、回放观看（N-12）、数据库与多进程（N-21 / N-22）、
多语言与换肤（N-18 / N-19）、移动端 App（N-24）。

**加功能前先查这张表**：命中的直接回「第一版不做」，不重新讨论；要做的条目整条删掉并记一条 ADR。

## 9. 版本号约定（建议，可改）

| 位 | 含义 |
| --- | --- |
| `0.1.x` | **只修缺陷**，不动规则、不动协议、不加功能 —— 随时可以替换线上包 |
| `0.x.0` | 规则条文 / 协议字段 / 卡池发生变化（旧回放不再可校验就属于这一档） |
| `1.0.0` | 第一版范围（`docs/22` 之外）全部完成，且美术素材到位 |

理由是**回放兼容性**：`replay:verify` 依赖开局血量、费用常量与状态机分支，
这些一变旧文件就校验不过（`README §10` 第 17 条）。所以「改数值」不是补丁级变更。
