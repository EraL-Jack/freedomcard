# 核心规则条文 · 10 血版（文件名沿用「8 血版」）

> 性质：**可直接实现的规则条文**，不是讨论稿。所有数值来自模拟验证（每组 6,000–8,000 局），
> 目标是「不加伤害上限，用规则和数值控节奏」。
>
> 适用版本：`docs/06` 的替代方案，落在 `app/packages/core/src/rules/`。
> 标注 **【改】** 的条目与现行实现不同；标注 **【保留】** 的沿用现行规则。
>
> **2026-10-22 拍板后的现状**：血量 **10**、先手首回合抽 **1**、除外档 **1/2/3/5/7**、霜痕档 **2/4/6**。
> 逐条依据与原文对照见 **§15 变更登记**。§3–§14 中凡标「8 血基线」的数字，是提血前的实测，
> 保留作推导记录，**不再作为验收线**。

## 1. 对局设置

| 项 | 值 | 说明 |
| --- | --- | --- |
| 指挥官血量 | **10** | 【改】原 15；2026-10-22 提血（§15 C-01，原 8） |
| 主卡组 | 30 张 | 【保留】同名上限 3 |
| 指挥官 | 1 张，开局置入指挥官区 | 【保留】不进牌堆、不参与洗牌 |
| 起手 | 先手 **5** 张；后手 **6** 张 | 【改】后手 +1 |
| 先手第一回合 | 自动充能 **0 张**；抽牌 **1 张**；**不可攻击**；可以出牌 | 【改】抽牌 0 → 1（§15 C-05，2026-10-22 校正） |
| 胜负 | 指挥官血量 ≤ 0 立即败北 | 【保留】 |

**1.1** 先后手由 1d6 决定，点数大者先攻（平手重掷）。

**1.2** 双方血量相同。不做「后手加血」。

**1.3 座位偏差由赛制消化，不由规则硬压。**

去掉了打脸门槛后，单局先手胜率仍约 **63%**（见 §12）。继续在规则里削先手会伤到节奏型卡组：
实测「先手首回合只能出 1 张 + 后手起手 +2」能把先手压到 54.7%，但炎刃会从 43.7% 掉到 39.9%。
因此：

- 单局规则**只保留**「先攻首回合充能 0 + 不可攻击」这一档补偿（抽牌已于 2026-10-22 恢复为 1 张，§15 C-05）；
- 决胜用 **BO3，双方各先手一次**；若 1:1，第三局由**前一局败者先攻**（Era 2026-10-19 拍板，H33；判和时无败者则掷骰）；
- 不在卡牌或血量上继续补偿座位。

## 2. 回合结构

六阶段顺序固定，不可跳过（【保留】A4-1）：

```
充能 → 重置 → 抽牌 → 主要 → 战斗 → 结束
```

| 阶段 | 自动发生的事 |
| --- | --- |
| **充能** | ① 从己方卡组顶取 **2 张**置入费用区（**先攻第一回合为 0 张**）；② 可额外把手牌/场上的**随从**置入费用区（数量不限，每张 = 1 费） |
| **重置** | 己方随从解除休眠（【保留】A9-2） |
| **抽牌** | 抽 2 张；先手第一回合抽 1 张 |
| **主要** | 出牌（随从 / 法术 / 设置法术） |
| **战斗** | 随从攻击 + 指挥官攻击（各一次） |
| **结束** | 结算回合末效果，交给对手 |

**2.1** 充能的第 ① 项是**强制**的：即使费用区已经很多，也要取 2 张。这是本版「降低空过」的基础。

**2.2** 充能的第 ③ 项是**可选**的，只允许**随从**（法术不能充能，【保留】X-2 原文口径）。

**2.3** 抽牌是手动点击卡组触发，抽完自动进入主要阶段（【保留】现行）。

**2.3.1**【新增】抽牌阶段的推进口径（Era 2026-10-22 拍板，§15 C-05）：

| 本回合该抽 | 推进方式 |
| --- | --- |
| **N > 0 张** | **手动**：停在抽牌阶段，玩家点卡组抽牌，抽完自动进主要 |
| **0 张** | **自动**：引擎补 `draw:completed` 后直接推进，不停住 |

**自动推进 ≠ 跳过抽牌阶段。** 事件流必须完整发出
`phase:changed(→ draw)` → `draw:completed` → `phase:changed(draw →)`，
客户端逐条播放，玩家仍能看到「抽牌阶段」这一拍。

这是「**所有动作原子化解耦**」（`docs/02 §4.3`）的落地要求：引擎只负责按序发事件，
界面按序播放；不许把多个阶段合并成一条事件、也不许一帧 reduce 完。

> 当前默认口径下（先手首回合抽 1、其余回合抽 2）不存在 0 张的抽牌阶段；
> 上表第二行是为「将来改数值或特殊模式」预留的统一行为，实现侧不要为它单开旁路 ——
> 手动与自动共用同一个 `advanceOnce`（ADR-0011）。

## 3. 费用系统

### 3.1 费用的定义

**费用不是数值，是费用区里的卡的数量。** 支付 C 费 = 从费用区取 C 张卡置入弃牌区（【保留】A5 补充 2）。

### 3.2 费用来源（三条）

| 来源 | 数量 | 说明 |
| --- | --- | --- |
| 每回合充能收入 | 2 张 / 回合 | 【新增】卡组顶直接进费用区 |
| 手牌/场上充能 | 任意 | 【保留】X-2，只限随从 |
| 指挥官受伤 | 每 1 点伤害 = 1 张 | 【保留】A5 补充 1，从卡组顶展示后进费用区 |

### 3.3 每回合可消耗上限（`maxCost`）

**【改】必须校验。** 现行实现完全没检查，1→3→5→10 只是状态值。

| 己方第 N 回合 | 1 | 2 | 3 | 4+ |
| --- | --- | --- | --- | --- |
| 本回合最多消耗 | 1 | 3 | 5 | 10 |

- 按**各自回合数**推进，不按全局回合（否则后手白拿一档）。
- 语义是「**本回合所有支付的总张数上限**」，不是单卡费用上限。
- 0 费牌不消耗额度。

**3.4** 支付顺序：先消耗费用区最前面的卡。充能收入追加在队尾。

**3.5** 费用区没有上限，回合结束时不清空（【保留】）。

> 实测：8 血 6 轮的局里，第 4 回合起费用区稳定过剩（平均剩 2.8 张），
> `maxCost` 只在前 3 回合起节流作用。这是预期行为：后期不该再卡费。

## 4. 召唤

| 项 | 规则 |
| --- | --- |
| 随从区 | **3 格**（【保留】B2 布局） |
| 召唤失调 | **无**。当回合召唤的随从当回合可以攻击 |
| 召唤费用 | **卡面费用 -1**，最低 0 |
| 同名上限 | 3 张（【保留】） |

**4.1** 减费只作用于**随从**。法术与设置法术按卡面费用支付。

**4.2** 减费发生在「计算支付额」时，不改卡面数据。实现上等价于
`pay = max(0, def.cost - 1)`，写在 `play.ts` 的支付入口。

**4.3** 不设「召唤力量上限」的硬限制。原因：硬上限会让抽到的高力量值随从打不出，
第 3 回合起空过率从 1.0% 涨到 **34.8%**，与「降低空过」直接冲突。

**4.4** 不设任何形式的召唤上限。硬上限会让第 3 回合起空过涨到 **34.8%**（§4.3）；
软上限的基准是「指挥官力量值」，而它已取消（§6.2.1），所以也没有可用的上限口径。

## 5. 战斗

### 5.1 攻击次数

- 每个随从每回合攻击 **1 次**，攻击后进入休眠，重置阶段解除（【保留】A9-2）。
- 指挥官每回合攻击 **1 次**（见 §6）。
- 先手第一回合不可攻击（【保留】A10-3）。

### 5.2 前排规则【核心改动】

> **对方随从区有随从时，己方随从不能选择对方指挥官作为攻击目标，必须攻击随从。**
> **对方随从区为空时，己方随从才能攻击指挥官。**

- 这是**目标合法性**的限制，不是伤害减免：不符合条件时直接不允许宣告。
- 指挥官**不受**前排限制（见 §6）。
- 嘲讽（taunt）优先于前排：对方有嘲讽随从时，必须先打嘲讽（【保留】A7）。

**5.3** 前排是「全局」判定，不分列。不做分列战线（3 列会让打不过的前排永久卡列，
先手胜率升到 82.2%）。

### 5.4 随从攻击随从

纯力量值比较（【保留】X-3）：

| 比较 | 结果 |
| --- | --- |
| 攻 > 守 | 防守方破坏 |
| 攻 < 守 | 攻击方破坏 |
| 攻 = 守 | 双方破坏 |

随从没有血量，**不掉指挥官血**。

### 5.5 随从攻击指挥官

**只剩一个前提：** 对方随从区**为空**（前排规则）。

**【改】不再比较力量值。** 只要场面是空的，任何随从都能打脸——1 力量值随从也能对指挥官造成伤害。
宣言时**直接结算伤害、直接扣血**，不进入力量值对拼，攻击方也不会因为「打不穿」而自爆。

| 攻击者力量值 | 伤害 |
| --- | --- |
| 1–3 | 1 |
| 4–6 | **2** |
| 7+ | **3** |

**【改】伤害由力量值决定**，不再默认 1。卡面 `damage` 字段保留为**例外覆盖**：
卡面写了伤害值就用卡面值（用于「低力高伤」的特殊设计）。

**5.5.1** 去掉力量值门槛后，节奏由「谁能打脸」变成「谁能清场」：

| 场景 | 结果 |
| --- | --- |
| 对方场上还有随从 | 必须先解场，一点血都打不到 |
| 对方空场 | 任何随从都能打，伤害按自身力量值分档 |
| 双方都清不干净 | 只有指挥官的基础 1 点在推进 |

这条改动把胜负从「随从能不能过墙」转成「**谁能把场面打空**」——
前排规则负责拖，清场能力负责兑现。

**5.6** 伤害值不因「攻击者力量值被临时加成」而重复计算——按宣告时的当前力量值取值一次。

**5.6.1** 实测影响（炎刃 vs 霜律，各 1,500 局）：

| 指标 | 保留门槛 | 去掉门槛 |
| --- | --- | --- |
| 随从伤害占比 | 30% | **46%** |
| 平均轮数 | 5.1 | **3.9** |
| 体系胜率 | 53 : 47 | **49.2 : 50.8** |
| 空过率 | 4.4% | **3.6%** |

### 5.7 指挥官受伤的连带效果【保留】

指挥官每受 1 点伤害 → 从卡组顶展示 1 张 → 置入**费用区**（A5 补充 1）。

- 逐点触发。3 点伤害 = 展示 3 次。
- **受伤展示就是「展示」**（Era 2026-10-21 拍板，D-234）：走与技能展示完全相同的
  展示动作 —— 因此同样 **触发「展示时」效果**（弓手直伤 / 织者召唤 / 侍僧加伤…）、
  同样的 **星轨 +1**，只是结算后进费用区而不是回牌库底。
  （此前是「只展示、不触发」，同一个词出现两种含义；审查里记为 PM-17。）
- 这条是「挨打 = 拿到资源」，本版**保留**：它让落后方有翻盘资源，且实测不影响平衡。

## 6. 指挥官

### 6.1 攻击【核心改动】

> **每个己方战斗阶段一次，指挥官对敌方指挥官造成 1 点伤害（基础值）。**
> **不比较力量值，不受前排限制；基础值不被力量值影响，但可被「指挥官伤害值 +N」类效果提升（§9 #9）。**

- 先手第一回合不可攻击。
- 这是全局唯一的「稳定时钟」：基础值恒定 1 点，膨胀只来自卡面明写的少量加成。
- 不设「每回合伤害上限」——基础值本身是 1 点/回合。

**6.2** 指挥官**不能**攻击敌方随从，唯一目标就是敌方指挥官。
理由：如果可以，它会变成「万能解场」，把前排规则的意义抹掉（旧版实测先手升到 66–95%）。

**6.2.1 指挥官没有力量值。**

- 不做任何比较，所以不需要数值；
- 伤害基础值 1 点，不被力量值影响（加成只来自卡面效果，见 §9 #9）；
- 不参与「随从打脸」的门槛判定（该门槛已删除）。

卡面首行只写 `指挥官`，不写力量值曲线、不写费用。

> 旧版有 `powerCurve = [0,1,3,5]` 与「力量值0-1-3-5 力量值提升，在每回合充能阶段执行」，
> 在删掉打脸门槛、并确认指挥官不攻击随从之后，它已经**没有任何结算作用**。
> 按 Era 2026-10-19 决定：**取消所有指挥官力量值的表述**。
> 代码里的 `powerCurve` 字段可保留作历史，但不参与任何判定。

### 6.3 成长性：不做通用规则，由各指挥官自己承担

**没有全局的「力量值→技能变强」公式。** 每个指挥官用自己卡面上的资源决定成长曲线，
资源来源不同、兑现方式也不同。

| 指挥官 | 成长资源 | 怎么累积 | 怎么兑现 |
| --- | --- | --- | --- |
| **炎刃军统领** | **除外区**（只算卡名含「炎刃」的卡） | 骑士/老兵/焚典/凤凰/卫士把炎刃卡除外，永久累积 | Ⅰ 按 **1 / 2 / 3 / 5 / 7** 张分档：召唤 → +1 力量值 → 破坏 → 伤害 +1 → 攻击后重置 |
| **霜律裁决官** | **霜痕**（Frost Mark） | 每冻结 1 个敌方随从 +1 层，永久累积、不随冻结解除消失 | Ⅰ 按 **2 / 4 / 6** 层升级：冻 1 → 冻 1+抽 1 → 冻 2 → 冻 2+抽 1 |

> 2026-10-22 拍板（§15 C-02 / C-03）：两套档位前移。**效果与顺序一个不改**，只把解锁门槛压进典型局峰值。
> 原值（1/3/5/7/9、3/6/9）在 3.7–4.6 轮的局里后半段不可达（`docs/23` D-1）。

**6.3.1** 两者的「味道」不同，不是同一套公式换个名字：

- 炎刃是**主动投资**：要把卡送进弃牌区、再除外，每一步都有取舍（骑士要放弃当回合 +1 还是留着回收）。
  资源是你自己「造」出来的。
- 霜律是**被动累积**：只要冻结发生就留下痕迹，不需要额外操作。
  但冻结本身是消耗性的（对手下回合就醒了），所以霜痕是「把一次性收益沉淀成永久成长」。

**6.3.1.1 统领Ⅰ的「选择一个随从」选谁（Era 2026-10-21 定）**

| 除外区炎刃数 | 效果 | 候选范围 |
| --- | --- | --- |
| 1 | 从弃牌区召唤（力量 ≤ 除外区炎刃数） | **己方弃牌区** |
| 2 | 本回合力量 +1 | **己方**场上 |
| 3 | 破坏（力量 ≤ 除外区炎刃数） | **双方**场上 —— 破坏是负面效果，只给己方等于只能自杀（issue #105） |
| 5 | 本回合对指挥官伤害 +1 | **己方**场上 |
| 7 | 一回合一次，攻击后重置 | **己方**场上 |

门槛为 **1 / 2 / 3 / 5 / 7**（2026-10-22 前移，§15 C-02；原 1/3/5/7/9）。
力量值一律按**卡面值**比较（与 1 档召唤、号令同口径，不吃临时加减）。

**6.3.2 霜痕规则文本**

```
霜痕（Frost Mark）
每当一个敌方随从被冻结，你获得 1 层霜痕。
霜痕永久累积，不随冻结解除而消失，也不随随从离场而减少。
对已处于冻结状态的随从再次施加冻结，不算「被冻结」：不获得霜痕，也不刷新状态。
```

**6.3.3** 裁决官 Ⅰ 的档位（目标限**未冻结**的敌方随从）：

| 霜痕 | 效果 |
| --- | --- |
| 0–1 层 | 冻结 1 个未冻结的敌方随从 |
| 2–3 层 | 冻结 1 个未冻结的敌方随从，抽 1 张 |
| 4–5 层 | 冻结 2 个未冻结的敌方随从 |
| 6 层+ | 冻结 2 个未冻结的敌方随从，抽 1 张 |

门槛为 **2 / 4 / 6**（2026-10-22 前移，§15 C-03；原 3/6/9）。
8 血基线实测每局平均堆到 **6.7 层**，第 3–4 轮能走到「冻结 2 个」；
10 血后轮数变长，峰值预计更高，顶档（6 层：冻 2 + 抽 1）应能稳定到达 —— **数值待复测回填，不再引用本节旧数字当验收线**。
玩家在每一轮都能看到层数变化，但不会一轮跳两级。

**6.3.4** 8 血基线实测（炎刃 vs 霜律，各 1,500 局，**档位为当时的 3/6/9**）：

| 指标 | 无霜痕 | 加霜痕（3/6/9） |
| --- | --- | --- |
| 霜律胜率 | 53.5% | **57.0%** |
| 每局霜痕 | — | **6.7 层** |
| 平均轮数 | 3.8 | 3.8 |
| 空过率 | 6.4% | 6.8% |

> 霜律本来就不弱（53.5%），加成长后到 57.0%。这是刻意的：**成长是净增强，不是平衡补偿**。
> 如果实测觉得偏强，把档位抬到 4/7/10（霜律回落到 55.7%），不要砍霜痕本身。
> 同时记住 §12.2：AI 低估炎刃约 7 个点，真人手里两套会更接近。

## 7. 伤害与血量

| 项 | 规则 |
| --- | --- |
| 初始血量 | **10**（2026-10-22 拍板，§15 C-01；原 8） |
| 血量下限 | 0，不为负 |
| 单回合伤害上限 | **不设**（明确不要） |
| 伤害来源 | 随从打脸（1/2/3）+ 指挥官 1 点（可被卡面效果加成，§9 #9） |
| 40 轮决胜 | **比指挥官血量，高者胜**；同血量 → 进入**即死模式**，此后任何一方掉血立刻判负 |

**7.1** 血量是公开信息，实时显示。

**7.2** 治疗目前不存在；若后续加入，上限为 **10**（与初始血量一致）。

**7.3 · 40 轮决胜（D-237，Era 2026-10-21）**

原口径是「40 轮未分胜负判和」，现已废止，改为两步：

1. **第 40 轮结束（全局回合 80）时比血量** —— 血量高者直接获胜，`reason = 'turn-limit'`。
2. **双方血量相同 → 不结束，进入即死模式**（`state.suddenDeath = true`，发 `sudden:death` 事件）。
   此后**任何一方受到 1 点及以上伤害，血量直接归零并判负**，`reason = 'sudden-death'`。
   即死模式只进入一次，之后每次换手不再重复裁定。

改口径的原因（连着两条）：

- **原「判和」在 BO3 里收不了尾** —— 判和「不计分但消耗一局」，而系列赛只认「有人拿到 2 胜」，
  三局打成 1:1 时永远没有胜者，房间会停在「等待下一局」。改成血量裁定后每局必有胜者。
- **即死模式给同血量一个收口** —— 比血量打平时不能判和（否则又回到上面的坑），
  也不该无限拖下去，于是定「先掉血者死」：它把僵局变成一个明确、双方都看得懂的竞速。

> **残余风险**（H50，已知未解决）：即死模式下若双方都再也无法造成伤害（例如双方场上都无随从、
> 指挥官攻击又被前排挡住），对局理论上可以无限持续。当前没有兜底计时器 —— 8 血节奏下实测未出现，
> 若真出现由玩家认输结束。要不要加「即死模式 N 轮后强制结束」待 Era 定。

### 7.5 信息可见性：只看「牌在哪个区」（Era 2026-10-22 拍板，§15 C-06）

**一条规则取代此前逐事件的枚举。** 一张牌对对手可见与否，**只取决于它当时所在的区**，
与「它怎么进来的」无关。

| 分类 | 区域 | 对手可见 |
| --- | --- | --- |
| **隐藏区** | 手牌、牌库 | **不可见**（连牌名都不可见） |
| **公开区** | 场上、**能量区（费用区）**、弃牌区、除外区、指挥官区、展示区 | **可见**（含牌名） |

**7.5.1 由此推出（都是规则的自然结果，不是新规定）：**

| 动作 | 起点 → 终点 | 对手看到什么 |
| --- | --- | --- |
| 抽牌 | 牌库 → 手牌 | 只知道「抽了 N 张」。牌名不可见 |
| 回合充能 | 牌库 → 能量区 | **能看到是哪张牌**（终点是公开区） |
| 手牌 / 场上充能 | 手牌 / 场上 → 能量区 | 能看到是哪张牌 |
| 打出随从 / 法术 | 手牌 → 场上 / 弃牌区 | 能看到 |
| 弃置、除外 | 任意 → 弃牌区 / 除外区 | 能看到 |
| 展示 | 任意 → 展示区 | 能看到 |

**7.5.2** 能量区属于公开区，因此**对手有权查看你费用区里的具体卡牌**，不是只知道张数。
支付费用（能量区 → 弃牌区）同样是公开动作。

> **呈现方式不由本条限定。** 按 B2-3（`docs/06`）区域格子默认只显示「区名 + 张数」、
> 点开看浮窗，这是界面规范；本条保证的是**信息对对手可得**，不是要求默认铺开。
> 底线：不得对对手隐藏内容，且必须提供查看全貌的入口。

**7.5.3 战报遵守同一判定。** 公开区的信息战报可以照实记（含牌名），
隐藏区的信息战报不得出现（只能记数量或「发生了一次抽牌」这类动作）。
战报不得比桌面更公开。

**7.5.4** 回放与服务端事件流**不受本规则限制**，全量保留（含对手手牌与牌库顺序），
否则无法复盘与调试。本规则约束的是**玩家视角的呈现**。

## 8. 关键词与前排的交互

| 情形 | 裁决 |
| --- | --- |
| 对方有普通随从，无嘲讽 | 只能打随从，任选 |
| 对方有嘲讽随从 | 必须先打嘲讽（嘲讽优先于「任选」） |
| 对方有嘲讽，但攻击者力量值不足以击杀 | 仍必须打嘲讽，然后按力量值比较自爆 |
| 对方空场 | **任何随从都能打脸**，伤害按自身力量值分档（1–3→1，4–6→2，7+→3） |
| 对方空场，攻击者力量值为 0 | 仍可宣告，造成 1 点伤害（最低档） |

| 指挥官被冻结 | 不适用：冻结只影响随从 |

## 11. 卡牌适配

### 11.1 费用整体下移一档

减费后实际支付 = 卡面 -1，所以**卡面费用不用改**，但设计新卡时要按「实际支付」思考：

| 卡面费用 | 实际支付 | 定位 |
| --- | --- | --- |
| 0 | 0 | 起手牌、填充 |
| 1 | 0 | 1 费节奏点（实际免费） |
| 2 | 1 | 主力低费 |
| 3 | 2 | 标准中坚 |
| 4 | 3 | 中后期 |
| 5 | 4 | 大怪 |
| 6 | 5 | 终结者 |
| 7 | 6 | 顶费 |

**11.2 注意**：卡面 1 费 = 实际 0 费，会变成「免费牌」。这类牌不能太多，
建议占比 ≤ 15%，否则起手节奏会失控。

### 11.3 伤害要按 10 血重估

| 伤害 | 占血量（10 血） | 占血量（8 血，旧） | 含义 |
| --- | --- | --- | --- |
| 1 | 10.0% | 12.5% | 常规 |
| 2 | 20.0% | 25% | 一次两成，重 |
| 3 | 30.0% | 37.5% | 三成，三次斩杀 |

**结论**：单次伤害的相对权重比 8 血下降约两成，**第一版不回调卡池**，
只在复测出现「打不动」时再放量。原有卡池约束（7+ 力、伤害 3 的随从全场 2–3 张）
作为上限保留，不是必须打满的目标。

### 11.4 之前两套 15 张卡的影响（**8 血基线的结论，10 血下需重估**）

`12-卡牌补充与霜律卡组.md` 里的数值是按 15 血设计的。下表是 8 血时的结论，
**10 血下不再直接沿用**（单次伤害权重降约两成），保留作参考：

| 卡 | 原设计 | 8 血下建议 |
| --- | --- | --- |
| 炎刃凤凰（7 费 7/7 伤害 2） | 伤害 2 | 保持：7 力量值 → 分档 3，但卡面写 2 就按 2；作为「可控终结者」 |
| 凛冬之刃（6 费 6/6 伤害 2） | 伤害 2 | 保持：6 力量值 → 分档 2，卡面值一致 |
| 霜律典狱长（5 费 5/5） | 无伤害 | 5 力量值 → 打脸 2，实际是隐性加强 |
| 所有「造成 1 点伤害」法术 | 1 点 | 8 血下 1 点 = 12.5%，比 15 血时重 25%；法伤可整体 -0，但**数量要减** |

**11.5** 去掉打脸门槛后，**低费随从也能稳定扣血**：1 费 2 力量值随从在两三个空场窗口里就能打掉 3–4 点。
这意味着「铺场 → 对方解不干净 → 连续打脸」成为可行路线，低费曲线不能过密。

建议：0–2 费的随从占总随从数 **≤ 40%**；3 费以上要有足够的交换能力（力量值 ≥ 费用），
否则场面清不干净，会被反过来打穿。

### 12.3 实装复核（2026-10-21，D-276）

> 本节**不改任何条文**，只登记「§12 的数字」与「实装引擎跑出来的数字」的差异，
> 防止把**模拟器口径**当成事实引用。完整分析见 `23-策划复盘-设计与体验问题.md` §D-8。
>
> 方法：用实装 `core` + 真实卡池 + 三套默认卡组跑 1200 局 AI vs AI（6 组配对 × 200 局，固定种子）。

| 指标 | §12 目标 / 实测 | 实装引擎（AI vs AI） |
| --- | --- | --- |
| 平均对局长度 | 3.8 轮 | **3.7 – 4.6 轮**（同向，可信） |
| 空过率 | 6.8% | **0.13 – 0.20 次/局**（同向，可信） |
| 指挥官技能发动 | 5.6 次 / 局 | **0 次 / 局** |
| 先手方胜率 | 56.5% | **25.5% – 50.5%（6 组全部 ≤ 50%）** |

**两处不可用的原因**（不是规则变了，是测量工具不够）：

1. `core/src/ai.ts` 的 `decideAiMove` **没有 `effect:activate` 与 `charge:put` 分支**，
   所以「技能 5.6 次/局」在实装里必然是 0（issue #137）。
2. 先攻方首回合「0 充能 + 0 抽牌 + 不可攻击」这一档，**只有会用手牌充能的人**才能补回来；
   AI 不会，于是 AI 先手等于整回合空过 —— 测出来的先手劣势是 AI 的缺陷，**不能据此改规则**。

**结论**：§12 的技能次数、体系胜率、先手胜率三行只能作为**模拟器参考值**；
修完 #137 之前，任何平衡调整都不要以它们为基线。

### 12.1 含法术卡组的偏差

如果卡组里法术**没有实际效果**，它们会变成死牌，把胜率推向另一边。
实测 23 随从 + 7 无效法术时，后手会涨到 60.2%（旧规则数据）。

**因此**：法术必须有可结算的效果；法术强度不足时，不要靠座位补偿去补，直接改法术。

### 12.2 AI 对炎刃的偏差

模拟用的是贪心 AI：它不会为「三回合后的凤凰」攒弃牌区，也不会判断「这张炎刃卡该除外还是该留着回收」。
霜律是线性的（有冻结就冻），AI 的操作上限更接近真人；炎刃是组合型，AI 明显偏低。

所以 **46.5 : 53.5 这个差距被 AI 放大了**。真人手里炎刃会更接近 50，
调整平衡时不要直接照这个数字去削霜律。

## 14. 一句话

**10 血；每回合白拿 2 费、随从再 -1 费；随从先打场面，场面一空就直接扣血——
不管它几力。指挥官没有力量值，每回合固定对敌方指挥官 1 点，不能攻击随从。**
**成长性由各指挥官自己的卡面承担：炎刃滚除外区（1/2/3/5/7 档），霜律滚霜痕（2/4/6 档），
两种资源来源不同、都永久累积，玩家每轮都能看到自己变强。**
先攻首回合少拿 2 费、不能攻击，座位差交给 BO3。

### 15.3 校准规则（一次只动一个旋钮）

血量是**节奏旋钮**（控轮数），档位是**体系旋钮**（控强弱）。不要同时调。

| 复测结果 | 动作 |
| --- | --- |
| 平均轮数 < 4.5 或 > 5.5 | 血量 ±1。**不要用档位调轮数** |
| 炎刃胜率 > 60% | 除外档抬一档 → 1/3/4/5/6。**不要回调血量** |
| 霜律胜率 > 60% | 霜痕档抬一档 → 3/5/7。**不要砍霜痕本身** |
| 顶档可达率 < 60% | 该体系档位再降一格 |
