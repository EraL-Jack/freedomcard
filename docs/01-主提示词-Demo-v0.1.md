## 2. 技术栈（已锁定）

- **运行时**：Node.js `>=22.12.0`（推荐 24 LTS）；包管理器 **pnpm 12.11.2**。
- **客户端**：TypeScript `5.9.3` + React `^19.3` + Vite `^8.3`；卡牌与桌面用 DOM + CSS 渲染，粒子/特效层可选 PixiJS（按需懒加载）。
- **样式**：Tailwind CSS `^4.3` + `@tailwindcss/vite`，mobile-first，断点 375 / 768 / 1024 / 1440（**v4 用 `@theme` 定义，无 `tailwind.config.js`**）。
- **服务端**：Fastify `^5.12` + Socket.IO `^4.8`（**权威服务器**）。
- **共享层**：pnpm monorepo；`packages/shared`（协议与类型）、`packages/core`（纯函数规则引擎，前后端同构复用）。
- **校验**：Zod `^4.6`。**测试**：Vitest `^5.0`（单测） + Playwright `^1.64`（端到端）。**日志**：pino。
- **部署**：Docker Compose + Nginx（HTTPS / WSS）。

**版本线以 `docs/02` §2 为准，照抄安装，不得自行升降级。** 理由与目录结构见 `docs/02-技术栈与架构规范.md`。

## 3. 架构约束（原子化 + 解耦，强制）

1. **单入口意图**：任何点击 / 拖拽 / 快捷键只能产生一个 `Intent`，不得直接改状态。
2. **服务器权威**：客户端只发 `Intent`；服务端校验后生成 `GameEvent[]` 并广播；客户端只做 `reduce` + 渲染。
3. **原子性**：一次 `Intent` 的规则处理整体成功或整体失败；失败返回 `Rejection{code, message}`，不产生任何副作用。
4. **纯函数规则**：处理器签名固定 `(state, intent, ctx) => Result<GameEvent[], Rejection>`；禁止 IO / 时间 / 随机 / DOM。
5. **插件化注册**：规则集中于注册表 `rules[type]`；新增卡牌或机制 = 新增文件 + 注册一行，**不得修改既有规则文件**。
6. **确定性**：随机数走种子 RNG（种子由服务端开局下发）；时间只取事件时间戳。相同种子 + 相同 Intent 序列 ⇒ 终局状态完全一致。
7. **不可变状态 + 事件溯源**：`GameState` 只能由 `reduce(state, event)` 演进；全量事件序列可回放。
8. **幂等**：每个 Intent 带 `seq`，重复 seq 直接丢弃，保证弱网重发不双结算。
9. **可观测**：每局落一份 `replay.json`（种子 + Intent 序列 + 状态哈希链）。
10. **分层纪律**：`core` 不得 import `net` / `view`；`view` 不得依赖 `core` 内部实现，只依赖类型与事件。

## 4. 交互与界面要求

- 关键操作必须**单指可完成**：点选卡牌 → 点选目标 → 确认；必须有「取消」与「撤销未确认操作」。
- **撤销的边界**：撤销只作用于**尚未 emit 的 UI 选中态**（已选卡牌、已选目标）；Intent 一旦 emit，客户端不得本地回滚，状态只能由服务端广播的事件演进。
- 拖拽是增强，不做唯一入口；桌面 hover 态在触屏用长按替代。
- 必须有：加载态、操作中态、非法操作反馈、断线提示与重连进度。
- 响应式：375×667 / 768 / 1440 三档均无横向滚动、无元素遮挡、无点击热区小于 44×44px。
- 动效 120–250ms，不阻塞输入；遵循 `prefers-reduced-motion` 提供「减少动效」开关。

## 5. 联机要求

- **大厅**：创建房间（生成 4–6 位房间码）/ 输入房间码加入 / 房间列表（可选）。
- **房间**：准备、开始、房主踢人、断线保留席位 **60s（`RECONNECT_GRACE`）** 可重连；回合无操作超时 **30s（`TURN_TIMEOUT`）** 由服务端自动结束回合。两个常量命名固定，禁止混用。
- **实时**：同城操作广播延迟目标 < 150ms；对手操作即时可见。
- **一致性**：每个事件后服务端计算状态哈希随广播下发，客户端比对，不一致即告警并记入测试报告。
- **弱客户端**：首屏 JS ≤ 1.5MB(gzip)；低端机降级到 30fps 仍可完整操作。

## 8. 验收标准

- [ ] 两台设备（PC + 手机）在同一房间打完整局，无卡死、无状态分歧。
- [ ] 断线 60s 内（`RECONNECT_GRACE`）重连可继续对局，席位与状态完全恢复。
- [ ] `packages/core` 核心规则路径单测覆盖率 ≥ 80%。
- [ ] 375 / 768 / 1440 三档布局无溢出、无遮挡。
- [ ] 测试报告与用户反馈报告已产出，结论明确（**可发布 / 有条件发布 / 阻塞，三选一**）。
- [ ] `logs/CHANGELOG.md` 覆盖全部交付件改动。

## 9. 禁止事项

- 禁止客户端结算战斗结果（必须服务端算）。
- 禁止把规则逻辑写进 React 组件或 socket 回调。
- 禁止用客户端本地时间做回合计时。
- 禁止在规则函数中使用 `Date.now()` / `Math.random()`。
- 禁止为赶进度把多层逻辑塞进单个文件。
- 禁止在未确认规则槽位的情况下自行「补齐」玩法。
