# 23 · 策划复盘：设计问题、流程体验与优化建议

> **性质**：策划视角复盘。**不改任何产品代码**；code 问题立 issue，设计问题落本文，规则数值一律进「待拍板」。
> **日期**：2026-10-21 · 交付件 D-276
> **方法**（三条，缺一条结论就不成立）：
> 1. 通读规则条文与实装（`docs/16`、`core/src/rules/*`、`cards.ts`、`ai.ts`、`TableScreen.tsx`）；
> 2. **真机跑完一局**人机对战（炎刃 vs 霜律，含新手引导 → 换牌 → 充能 → 出牌 → 战斗 → 结算全流程）；
> 3. 用**实装引擎 + 真实卡池 + 三套默认卡组**跑 1200 局 AI vs AI（6 组配对 × 200 局，固定种子），取对局形状。临时脚本跑完即删，不进仓库。
>
> **判定口径**：不看「有没有 bug」，只看三个设计目标在实装里兑现了多少 —— **节奏可控 / 成长可见 / 进攻有收益**。

## 一、判定

| 口径 | 判定 | 依据 |
| --- | --- | --- |
| 作为「能顺畅打完一局」的 Demo | **有条件发布** | 4 轮打完、无卡死、无阻塞缺陷；条件是 §七 的 5 条拍板里有 3 条给出结论 |

## 三、设计问题

> 分级：**P0** = 让核心动机不成立，必须拍板；**P1** = 明显削弱体验或让结论不可信；**P2** = 打磨。
> 每条给「现象 / 证据 / 为什么是问题 / 选项 + 推荐 / 代价」。**没有一个数值是我替你定的。**

### D-1（P0）成长体系装不进 4 轮：一半的档位在对局里不存在

- **设计目标**：三套指挥官各自「滚资源 → 分档兑现」（`docs/16 §6.3`、`docs/17 §2.2`），玩家每轮都能看到自己变强。
- **事实**：平均 3.7–4.6 轮。真人局除外区 **0**；AI 峰值 除外 3.7–5.0 / 霜痕 4.5–5.5 / 星轨 7.6–10.1。
- **对照档位**：

| 体系 | 档位 | 4 轮局的可达性 |
| --- | --- | --- |
| 炎刃（除外区） | 1 / 3 / **5** / **7** / **9** | 1、3 档能到；5 档要打满 4–5 轮；**7 / 9 档基本不可达** |
| 霜律（霜痕） | 3 / 6 / **9** | 3 档稳定、6 档偶尔；**9 档不可达** |
| 星轨（星轨层） | 3 / 6 | 两档都能到，但**到 6 层就封顶**，之后没有成长 |

- **为什么是问题**：这不是「回合少一点」，是**三条成长曲线各自被砍掉了后半段**。玩家永远体验不到「练成」的那一下，成长线退化成「小加成」；而 `docs/16 §12` 把「3.8 轮偏快」当成一个可接受的小瑕疵，低估了它对玩法身份的影响。
- **选项**：
  1. 血量 8 → 10~12（文档实测会偏炎刃 60%+，需要在卡池上给霜律/星轨补中期兑现）；
  2. **档位前移**（除外 1/2/3/5/7；霜痕 2/4/6；星轨 2/4）—— 不动对局长度，只让现有轮次里能摸到高档；
  3. 加快资源获取（受伤展示同时给 1 层对应资源）；
  4. 不改，第一版就定位成「短局版」，把「滚资源」的话术从宣传里拿掉。
- **推荐**：**②**，并把 ① 作为第二阶段。理由是 ② 只动数值、不动规则、不动节奏，可以在同一批里回滚。
- **代价**：② 会让后期档位更早到达，平衡必须重跑（且要先把 #137 的 AI 修好，否则重跑没有意义）。

### D-2（P0）打脸的收益被三重抵消，甚至为负

- **规则现状**：指挥官每受 1 点伤害 → 对手从卡组顶**展示** 1 张 → 进**费用区**；且这次展示**触发「展示时」效果**（D-234）。
- **也就是说**：我打对手 1 点，对手得到 —— ① 1 张费用；② 若他是星轨，+1 层星轨；③ 被他展示到的卡若写「展示时：对敌方指挥官造成 1 点伤害」（星轨弓手），**我要掉 1 点血**。
- **证据**：真机局里每次打脸，战报都是「指挥官受到 1 点伤害 → 展示：霜律新兵 → 电脑 血量 7」，对手费用区同步 +1；AI 局里星轨能堆到 10.1 层，其中相当一部分来自挨打。
- **为什么是问题**：这套规则同时说「打脸是主要输出」（§5.5）和「挨打是资源」（A5 补充 1），再用 D-234 把「挨打」升级成「挨打 = 资源 + 成长 + 可能反伤」。于是在场面僵持时，**最优解是不进攻** —— 谁先动手谁吃亏。这与「不加伤害上限、用规则控节奏」的初衷正好相反。
- **选项**：
  1. 受伤展示**不触发**「展示时」效果（回到 D-234 之前），只给费用；
  2. 保留触发，但受伤展示**不进费用区**（削弱「挨打 = 资源」）；
  3. 保留，但**每回合受伤展示上限 2 张**（超额不展示、只掉血）。
- **推荐**：**①**。D-234 解决的是「同一个词两种含义」的一致性问题，但代价是打开了一条反伤链；一致性可以用「受伤展示只在**自己回合**触发效果」这类更窄的口径修复，不必让整个结算链都触发。
- **代价**：星轨会少掉一块「挨打也涨」的被动成长，需要在星轨卡面上补一点（例如观测者Ⅱ 从「展示时 +1」扩展到「受伤展示也 +1」）。

### D-3（P0）0 费随从是「免费站场 + 免费法力」

- **规则现状**：随从实际支付 = 卡面 −1（最低 0）；充能 1 张随从 = **1 费，与卡面费用无关**。
- **于是**：一张 0 费随从 = 免费上场 + 需要时充成 1 费。它比任何 1 费牌都强（同样免费，但更灵活）。
- **密度**：炎刃 23 张随从里 **10 张**是 0 支付（斥候 3 / 新兵 2 / 先锋 3 / 军师 2）；霜律、星轨同样各有一套 0 费位。`docs/16 §11.2` 只警告了「1 费牌 ≤ 15%」，**没有警告 0 费**。
- **证据**：真机局第 1 回合（后手、maxCost = 1）铺满 3 格，费用区一张未动。
- **为什么是问题**：卡池的「费用曲线」本来是自平衡旋钮，0 费牌把两端都占了（出场 + 法力），任何按曲线做的强度估算都会失效；并且它直接绕开 `maxCost` 的前期节流（D-4）。
- **选项**：
  1. 充能产出 = **卡面费用**（0 费牌充能得 0）—— 让 0 费牌只能「免费上场」，不能「免费当法力」；
  2. 0 费牌**每回合最多 2 张**（类似 maxCost 的第二条额度）；
  3. 只限卡池密度（0 支付随从 ≤ 6 张/套）。
- **推荐**：**① + ③**。① 修转化率，③ 修密度；两者都不动规则条文的主干。
- **代价**：① 会削弱「手牌换费」这个引擎（`docs/13` 里它是救命机制），需要确认炎刃/霜律在高费卡打不出时仍有出路。

### D-4（P1）`maxCost` 的 0 费豁免，正好放过了最该节流的牌

- **规则**：本回合所有支付总张数上限 1/3/5/10；**0 费不占额度**（`docs/16 §3.3` / §9 第 5 条）。
- **后果**：第 1 回合的「上限 1」只约束付费牌，免费牌想下几张下几张 —— 我这一局下了 3 张。
- **建议**：并入 D-3 的 ②。单独改也行，但两条一起改才闭环。

### D-5（P1）手牌充能的转化率和卡面价值脱钩，取舍被压平

- **规则**：手牌 / 场上的随从都能充能，每张 1 费，不看它是 1 费小兵还是 7 费凤凰。
- **后果**：「留牌还是换费」本来是最有张力的决策，现在变成「都一样，随便换」；高费卡打不出时换 1 费，心理上还很亏。
- **选项**：手牌充能 = 卡面费用（强牌换更多费，但会更快烧掉牌库）；场上充能 = 1 费（回收弱随从的出口）。
- **推荐**：值得一试，但**排在 D-3 之后** —— 两条都改会同时动「费用收入」和「卡牌价值」两根轴，不好归因。

### D-6（P1）文档口径与实测不符：指挥官才是主输出轴

- **数据**：伤害构成 随从打脸 5.3–7.8 : 指挥官 5.3–7.6，约 **1:1**。
- **`docs/16 §5.5.1` 的说法**是「谁能清场谁兑现」，把随从写成主输出。
- **实测**：指挥官每回合稳定 1 点、不受前排阻挡、不被冻结 —— 4 轮局里它稳定贡献一半伤害。随从更像「清场工具 + 偶尔兑现」。
- **建议**：**这是可接受的设计**（稳定时钟是这套规则的锚），但文档口径要改：指挥官是**主伤害轴**，随从是**节奏轴**。口径不改，后续所有「加强随从」的平衡动刀都会打偏。

### D-7（P1）先攻首回合的「空过感」，以及座位偏差还没有可信结论

- **规则**：先攻首回合 0 充能、0 抽牌、不可攻击（`docs/16 §1`）。
- **真机体感**：对手先手那一回合，桌面只是「对手回合」四个字，没有一句「本回合先攻方不能攻击」；新手会以为卡了。
- **数据**：AI 局先手胜率 25.5%–50.5%，但因为 AI 不用手牌充能（先手 AI 真的整回合空过），**这组数字不能作为「先手弱」的证据**。
- **建议**：① 先修 #137，再用同一套引擎重跑；② 无论结论如何，UI 都该给先手一句解释；③ 如果重跑确认先手确实偏弱，优先动「首回合抽 1 张」而不是动血量（血量牵一发动全身）。

### D-8（P1）平衡基线不可复现，文档却当成事实

- `docs/16 §12` 的「指挥官技能 5.6 次/局」「先手 56.5%」「体系胜率 43:57」来自**外部模拟器**，不是实装引擎。
- 实装跑出来：技能 **0 次/局**、先手 25.5%–50.5%。
- **建议**：在 §12 顶部加一行「**模拟器口径，未在实装 AI 上复现**」，并在 #137 修完后重跑、用实装数字替换。否则下一次调平衡一定从错误的基线出发。

### D-9（P2）信息层：战报不像「给玩家看的战报」，像事件流镜像

| 问题 | 证据 | issue |
| --- | --- | --- |
| 对手抽到的牌名被公开，与「对方手牌 N 张」自相矛盾 | 开局战报逐张列出「电脑 抽到 霜律审判…」 | **#136（待拍板）** |
| 每回合 5 行阶段流水 + 未映射事件名（`draw:completed` / `trigger:defend`） | 一局 40 行阶段噪音 | #121（已补证据） |
| 200 条上限后 React key 冲突，行可能重复/丢失 | 控制台刷 `same key 201` | **#135** |

- **为什么重要**：战报是玩家唯一的复盘凭据。它现在是「引擎说了什么就印什么」，而不是「玩家需要知道什么」。

### D-10（P2）结算页只有「输赢」，没有「为什么」

- 现状：`败北 / 对局结束 / 你的指挥官生命归零 / 返回主界面 / 查看回放（暂未开放）`。
- 缺的第一层是**下一步**（再来一局，#125 已转需求），第二层是**这局发生了什么**（回合数、伤害构成、成长峰值）。
- **建议**：结算页加 3 个数字就够 —— `打了 N 回合` / `随从造成 X 点、指挥官造成 Y 点` / `资源峰值 Z`。超过 3 个就变报表，不做。

## 四、流程体验问题

| # | 问题 | 实测 | 影响 |
| --- | --- | --- | --- |
| E-1 | **六阶段手动推进**，其中 2 个阶段没有决策（重置瞬穿、抽牌只有一下点击） | 每回合 3–4 次「推进阶段」 | 单回合 12–15 次点击，4 轮局 ~80 次 Intent |
| E-2 | **出牌 4 步**：选卡 → 出牌 → 选位置 → 确认支付 | 每次出牌 3–4 次点击 | 一张牌的操作成本高于它的决策价值 |
| E-3 | **每次出牌都弹「选支付哪 N 张」** | 费用区 3 张、支付 2 张 → 必弹 | 打断节奏；而费用卡的「身份」只对炎刃（弃牌区）有意义 |
| E-4 | 先攻首回合没有任何解释 | 见 D-7 | 新手以为卡了 |
| E-5 | 引导只覆盖 60% 的核心循环 | 3 步：充能 / 推进 / 出牌；无换牌、无费用上限、无指挥官技能 | 第一次进桌就会踩空（#117） |
| E-6 | 成长资源只有顶栏一个小标签（`除外区「炎刃」0`） | 无「还差几张到下一档」 | 「变强」这件事不可见，等于没有 |
| E-7 | 战报不可回溯 | 200 条截断、无筛选、无「只看我」 | 复盘只能靠记忆 |
| E-8 | 危险按钮相邻 | 「确认认输」贴「不换牌」、「取消攻击」贴「认输」 | #120 已立项 |
