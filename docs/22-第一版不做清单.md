# 22 · 第一版不做清单（C2-2 起草，2026-10-21）

> 来源：`docs/21` P-08 / C2-2 —— 「第一版明确**不做**的功能」这一栏一直空着，
> 于是每加一个功能都要临场判断「这算不算第一版」，范围会悄悄膨胀。
> Era 的原话是「C2-2你先起草吧」，故本文件是**草案**：你可以逐条划掉或改写，
> 我把改动回填进状态列。
>
> 判定口径只有一条：**不做它，两个人能不能顺畅打完一局？**
> 能打完 → 进本清单；打不完（缺了它就卡住 / 结果不可解释）→ 属于第一版。

---

## 一、玩法

| 编号 | 不做 | 为什么 | 什么时候做 |
| --- | --- | --- | --- |
| N-01 | **对手回合主动出牌 / 响应窗口** | 需要先定义「可响应时机 + 可响应动作范围」，卡池里也还没有响应型卡（`docs/21` P-04 的核实结论） | 出现第一张「对手回合可用」的卡时 |
| N-02 | 3 人及以上对局 | 前排、嘲讽、伤害裁定全是二人语义；引擎没验证过 3+。房屋容量已收到 2（T-07 / D-244） | 多人规则条文写好之后 |
| N-03 | 备牌 / 局间换卡组 | H37（Era 2026-10-20）已明确「不允许更换卡组」，BO3 中途换牌等于改赛制 | 需要长赛制（BO5 / 征服制）时 |
| N-04 | 卡牌收集 / 合成 / 升级 | 第一版所有卡都直接可用（`CARD_POOL` 47 个 defId），没有稀有度与持有量概念 | 需要长线成长时 |
| N-05 | 伤害类型（穿透 / 治疗 / 护甲） | 现在只有「血量 8 + 打脸伤害」一条线，多类型会把 `combat.ts` 的分支炸开 | Era 给出伤害类型条文之后 |
| N-06 | 即死模式的兜底计时 | H50 的残余风险：双方都打不出伤害时理论可无限拖。目前只靠 40 轮血量裁定进入即死，再由「掉血即负」收尾 | 真出现无限对局时（记录在案，不是忘记） |
| N-07 | AI 难度选择 / 多套 AI 策略 | 人机对战（D-242）只用于自测与熟悉卡组，一个「按规则走完能走的一步」的 bot 就够 | 有人要拿 AI 当练习对手时 |

## 二、系统 / 联机

| 编号 | 不做 | 为什么 | 什么时候做 |
| --- | --- | --- | --- |
| N-08 | 账号 / 登录 / 云端进度 | 全部状态在本机 localStorage（昵称、卡组、引导已看）。没有用户系统就没有「跨设备」这件事 | 需要多设备同步或好友关系时 |
| N-09 | 好友 / 私聊 | 沟通走外部工具。对战桌右侧那块「对话框（占位）」**已整块删除**（D-307 / #122）—— 空面板只会让玩家以为消息没加载出来 | 有常驻玩家群时 |
| N-10 | 旁观 / 观战 | `docs/21` P-05 结论「暂时不做」：协议没有 `room:watch`，观战推送也没有语义 | 有人要「看朋友打」时 |
| N-11 | 房间列表 / 匹配 / 天梯 / 排行 | 只有房间码 + 人机两种入口（B1 明确不需要大厅） | 玩家多到房间码不够用时 |
| N-12 | 回放观看入口 | 记录一直在写（`app/replays/`），**观看**入口置灰（D-183 / ADR-0041）：公网隧道月流量有限 | 流量不再是约束时，改一个常量即可 |
| N-13 | 进程重启后恢复对局 | 房间与状态全在内存；重启即丢。回放文件还在，但房间不重建 | 需要长时间在线的正式服务时 |
| N-14 | 断线重连之外的容错（切设备 / 换浏览器续打） | 重连凭据存在 localStorage，换浏览器等于换身份 | 同 N-08（有了账号再说） |

## 五、这份清单怎么用

1. **加新功能前先查这里**：命中的条目直接回「第一版不做」，不必重新讨论。
2. **要做的条目**：把该行整条删掉，并在 `logs/DECISIONS.md` 记一条 ADR 说明「为什么现在做」。
3. **不在这份清单里的功能**：默认属于第一版范围 —— 但仍要按 `docs/09` 走「假设 / 待确认」流程。
