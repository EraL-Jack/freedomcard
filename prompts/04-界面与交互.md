## 任务

## 具体要求

### 4.1 页面

> **缺省骨架** —— 下面四页是「联机对战通常需要的页面」示例，**最终以 `docs/06` B1 的实际输入为准**：
> Era 说不需要的页面不许建；Era 提出的额外页面必须建。

1. 大厅：昵称输入、创建房间、输入房间码加入、房间列表。
2. 房间：席位显示、准备按钮、房间码复制、房主开始按钮。
3. 对战桌：对手区 / 自己场面 / 手牌区 / 资源区 / 牌库与弃牌堆 / 结束回合按钮 / 回合指示器。
4. 结算：胜负、关键数据、再来一局。

### 4.2 交互（单指可完成）
- 出牌：点击手牌 → 卡牌浮起 + 可选目标高亮 → 点击目标/放置区 → 确认或再点一次取消。
- 攻击：点击随从 → 高亮可攻击目标 → 点击目标确认。
- 一切操作均支持「点击替代拖拽」；拖拽作为增强同时支持。
- 非法操作：按钮置灰 + 轻提示（如「费用不足」），禁止静默无响应。
- 手牌过多时横向滚动或扇形堆叠，保证每张可点。

### 4.3 响应式

> **缺省骨架** —— 下表的分区方式、行列数依赖 `docs/06` B2（布局）与 B5（移动端形态）的输入。
> 横屏还是竖屏、是否锁定横屏、单手还是双手操作，都要先问 B 组，不许照下表反推。

| 断点 | 布局（缺省示例） |
| --- | --- |
| 375×667 | 竖屏：手牌单行滚动，场面网格 2×4，操作按钮贴底 |
| 768 | 平板：场面网格 3×5，手牌放大 |
| 1440 | 桌面：全宽布局，hover 预览、快捷键（空格结束回合、Esc 取消） |

- 触屏热区 ≥ 44×44px；禁止横向滚动；安全区内边距适配刘海屏。

### 4.4 状态与反馈
- 必须有：加载态、等待对手态、操作中态（禁用重复提交）、重连中态、断线态。
- 动效 120–250ms，不阻塞输入；提供「减少动效」开关并遵循 `prefers-reduced-motion`。
- 对手操作立即可见（特效 + 文字日志）。

### 4.5 性能
- 特效层（如 PixiJS）动态 import，不进入首屏包。
- 列表虚拟化或分帧渲染，避免大场面掉帧。

## 约束

- 组件内禁止出现任何规则计算（如「这张牌能不能出」必须问 `core` 的校验函数或服务端返回的 `legalActions`）。
- 状态只从事件流演进（`reduce`），禁止在组件里 setState 出「假状态」。
- 禁止在渲染层硬编码颜色以外的业务常量（费用、血量等从 state 读）。
- 客户端不得引入 Zod 做运行时校验（只允许 `import type`），避免无谓推高首屏体积（实测约 24 kB gzip）。
