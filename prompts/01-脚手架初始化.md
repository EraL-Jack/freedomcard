# 提示词 01 · 脚手架初始化

> 前置：已读 `docs/01-主提示词-Demo-v0.1.md` 与 `docs/02-技术栈与架构规范.md`。
> 本步产物：`D-101`、`D-105`、`D-106`（骨架版）。
> **版本线**：严格按 `docs/02` §2 锁定的版本安装，不得自行降级或升级（见「具体要求」第 0 条）。

---

## 角色

你是本项目主程。本步只搭骨架，不实现具体玩法。

## 任务

在 `app/` 下建立 pnpm monorepo 骨架，保证「一条命令起全栈」。

## 具体要求

0. **版本线（照抄，不得改动）**：Node `>=22.12.0`（本机 22.22.2 / 24.14.0 均可，Docker 镜像用 `node:24`）；包管理器 **pnpm 12.11.2**。依赖：`typescript@5.9.3`、`react@^19.3`、`vite@^8.3`、`tailwindcss@^4.3` + `@tailwindcss/vite@^4.3`、`socket.io@^4.8` / `socket.io-client@^4.8`、`fastify@^5.12`、`zod@^4.6`、`zustand@^5.0`、`immer@^11.1`、`vitest@^5.0`、`playwright@^1.64`。
1. `pnpm-workspace.yaml` 声明 `packages/*`。
1a. 根 `package.json` 写 `"engines": { "node": ">=22.12.0" }` 与 `"packageManager": "pnpm@12.11.2"`；各包统一 `"type": "module"`；ESLint 用 flat config（`eslint.config.js`），不用 `.eslintrc`。
2. 建立四个包：`shared`、`core`、`server`、`client`，全部 TypeScript + `strict: true`，根目录共享 `tsconfig.base.json`。
3. `shared`：导出空的 `Intent` / `GameEvent` / `GameState` / `Rejection` 类型与 `schema.ts`（Zod 占位）。
   **Zod 使用边界**：运行时 `.parse()` 只在 `server` 入站校验处调用；`client` 只允许 `import type`，不得引入 Zod 做运行时校验 —— 实测仅引入一个 `z.object` 就把首屏产物推到 gzip 24.17 kB，而客户端校验的是自己刚发出去的数据，没有收益。
4. `core`：导出 `engine.ts`（`reduce` / `applyIntent` / `stateHash` 三个函数签名 + `TODO(slot)` 实现）、`rng.ts`（种子 RNG，**必须实现完整**）、`registry.ts`（空注册表）。
5. `server`：Fastify 起 HTTP，`/health` 返回 `{ ok: true, version }`；Socket.IO 挂载在同一端口，实现 `echo` 事件用于连通性验证。
6. `client`：React + Vite + Tailwind；一个页面，显示「服务端已连接 / 未连接」状态，调用 `/health` 与 socket echo。
7. **Tailwind v4 配置（v4 已无 `tailwind.config.js`，按下面三条做）**：
   - 安装 `tailwindcss` 与 `@tailwindcss/vite`，在 `vite.config.ts` 的 `plugins` 里加入 `tailwindcss()`；
   - 全局 CSS 首行写 `@import "tailwindcss";`（不是 `@tailwind base/components/utilities`）；
   - 自定义断点写在同一 CSS 文件，**五个必须全部显式重定义**：
     `@theme { --breakpoint-xs: 375px; --breakpoint-sm: 768px; --breakpoint-md: 1024px; --breakpoint-lg: 1440px; --breakpoint-xl: 1920px; }`
     缺任何一个都会混入 Tailwind 默认值导致断点顺序倒挂（默认 `xl=1280px` 会夹在本项目 `md=1024` 与 `lg=1440` 之间，使 `xl:` 反而早于 `lg:` 生效）。
     工程中**禁止使用 `xl:` / `2xl:` 变体**，只用上述五档；注意 `sm/md/lg` 的含义已被本项目覆盖，不再是 Tailwind 默认值。
   - **验收时查 media query，不要查 CSS 变量**：v4 会把断点编译成 `@media (width>=375px)` 这样的字面值，`--breakpoint-*` 变量会被 tree-shake 掉，搜变量会得到假阴性。
   禁止创建 `tailwind.config.js`，禁止使用 v3 的 `theme.extend.screens` 写法。
8. ESLint + Prettier 生效；`pnpm lint`、`pnpm typecheck`、`pnpm test` 三个脚本可用。
9. **git 仓库初始化（必做 —— `docs/03` §4 的载体）**：
   - **本工作区已于 2026-10-13 执行 `git init`（分支 `master`，尚无提交）**，执行方只需确认 `git status` 可用即可；若换环境重来，在**工作区根目录**（`app/` 的上一级）执行 `git init`；
   - 根目录 `.gitignore` 必须忽略：`node_modules/`、`dist/`、`dist-ssr/`、`.vite/`、`coverage/`、`*.tsbuildinfo`、`playwright-report/`、`test-results/`、`.workbuddy/`；
   - 首次提交绑定 `D-101`，commit message 形如 `chore(D-101): 初始化 monorepo 骨架`；
   - 未执行本步 → 验收不通过。没有 git，变更日志与 commit 的对应关系无从谈起。
10. **`pnpm install` 必须返回 `exit=0`**：pnpm 10+ 默认不执行依赖的安装脚本，本项目链路里 `esbuild` 会触发 `ERR_PNPM_IGNORED_BUILDS` 并以非 0 退出。若不处理，`pnpm install && pnpm dev` 会被 `&&` 短路，`dev` 永远不执行（表现为「依赖明明装上了、构建也能跑，但脚本链第一步就断」）。

    **已定案处置（`S1`，实测对照确凿）**：在 `pnpm-workspace.yaml` 写 **白名单键 `allowBuilds`**：

    ```yaml
    packages:
      - 'packages/*'
    allowBuilds:
      esbuild: true
    ```

    生成方式（推荐，避免在键名上出错）：先 `pnpm install`（会失败），再 `pnpm approve-builds --all` —— 该命令非交互，会**自动把待批准清单写入 `pnpm-workspace.yaml`**，无需手抄。

    **⚠️ 键名陷阱（实测踩过）**：pnpm 12 的键名是 **`allowBuilds`**；pnpm 10 的 `onlyBuiltDependencies` 在 pnpm 12 下**已不被识别**（`pnpm config get onlyBuiltDependencies` 返回 undefined，写了等于没写，退出码仍为 1）。同理 `.npmrc` 里的 `dangerously-allow-all-builds=true` 在 pnpm 12 也无效；CLI flag `--dangerously-allow-all-builds` 虽有效但等于全局放开，供应链风险最高，**不采用**。

    **实测对照（Vite 8 + Tailwind 4 + tsx，35 个包，干净重装）**：无白名单 `exit=1`；带 `allowBuilds: { esbuild: true }` `exit=0`，且仅 `esbuild` 一个包需要批准（`@tailwindcss/oxide` 是平台可选依赖，无 postinstall，不需批准）。

    新依赖若带 postinstall（如 `playwright`、`sharp`），需**追加进白名单**再重装，不要改用全局放开。

## 约束

- 不得写入任何玩法逻辑。
- `core` 不得 import `server` / `client` 的任何东西；`shared` 不得 import 其他三个包。
- 所有跨包引用走包名（`@app/core`），禁止相对路径跨包。

## 验收

- [ ] `pnpm install` 退出码为 0（`pnpm install; echo $?`）；非 0 则按第 10 条处置后再继续。
- [ ] `pnpm install && pnpm dev` 后，浏览器打开客户端能看到「服务端已连接」。
- [ ] `git status` 可用，且 `git check-ignore -v .workbuddy` 有输出（确认记忆与实测残留不会被跟踪）。
- [ ] `pnpm typecheck` 与 `pnpm lint` 零错误。
- [ ] `core/rng.ts` 有单测，且同种子两次运行输出一致。
- [ ] 版本核对：`pnpm why typescript react vite tailwindcss` 输出与第 0 条版本线一致（防装出旧版）。
- [ ] Tailwind 生效核对：页面出现 Tailwind 样式，且工程中不存在 `tailwind.config.js`。
- [ ] 断点核对：产物 CSS 中存在 `@media (width>=375px)` 与 `@media (width>=1440px)`。
