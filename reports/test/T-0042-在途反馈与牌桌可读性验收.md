## 3. 三个取舍

### 3.1 #158 的「在途」终点设为队列排空，而不是 ack 回来

`send()` 里的 `socket.emit` 没带 ack 回调，能等到的只有随后那条 `game:events`；
而 `game:events` 到了 ≠ 玩家看见结果 —— 事件要按 `FX_MS` 逐条播放，回合切换那串能播一两秒。
**慢的不是网络，是播放。** 所以终点定在 `pump()` 的 `finally` 里「队列排空」，语义是
「玩家眼睛追上了服务器」。

`game:events` 被拒（非 `accepted`）的分支不产生事件、队列永远排不空，
必须在 `onGameEvents` 里单独 `endSyncing()` —— 这是第二个收尾点。

`INTENT_WAIT_MS = 10_000` 是**兜底看门狗**，不是正常路径时长：没有它，
一条被吞掉的事件会让按钮永久置灰，玩家只能刷新。

### 3.2 #159-1 只挪回合横幅，不挪全部 FX

伤害 / 裁决 / 收入是**结算**提示，此刻玩家没有可点的操作，居中才在视线焦点上。
回合横幅不一样：它出现的那一刻玩家正要去点随从格，而它是 `pointer-events-none` ——
**点得到、看不见**，操作照旧成功，玩家却不知道自己点到了哪里。这是最坏的一种遮挡。

### 3.3 #159-2 是「不渲染」而不是「调成灰色」

指挥官区恒有 1 张，那个 `1` 没有信息量，只制造「血 10 1」这种误读。
张数只在**数得清、且会变**的区域才有意义（弃牌 / 除外 / 费用区）。
判据直接落在 `showCards` 上，不新增开关 —— 看得到卡的地方就不显示张数。

## 5. 一次假红：测试量错了对象

首跑「回合横幅不压随从格」是红的，但**不是样式没生效**：报告里的几何是
`y=337.5`（居中），而修后应是 `y=64`（`pt-16`）。

根因在测试写法：点「结束回合」后，播放队列里**先**播「结束阶段」（`kind: 'phase'`，本来就居中），
「第 N 回合」（`kind: 'turn'`）排在后面。原写法「`fx` 一可见就量尺寸」量到的是前一条横幅，
测的根本不是本轮修的东西。

改为按**文案**锁定后转绿：

```ts
await expect(fx, '回合横幅应该出现').toContainText('回合', { timeout: 30_000 });
```

归入通用做法：**先用 testid 定位到「某类元素」，再用文案锁定「这一个」**——
逐条播放的队列里同类元素会连续换人。
