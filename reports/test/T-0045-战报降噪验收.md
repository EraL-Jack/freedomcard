## 3. 三个取舍

### 3.1 判据是「主语」，不是「重要性」

机制行 = 主语是**系统**的四个事件（阶段切换、重置、自动充能、费用上限）。
「Solo 抽了 1 张」不进机制行：它是玩家的动作结果，一回合 1~2 行。
写成「主语」而不是「重不重要」，才能回答「下一条新事件归哪边」。

### 3.2 折叠而不是删除

战报是当前**唯一**复盘手段（回放入口置灰，D-183）。机制行是时间轴骨架，
删掉是丢信息。所以留开关 + 「另有 N 条」的计数，让玩家知道没丢。

### 3.3 合并：被另一条事件完整概括的位移不成行

`cost:spent` 已经说了「消耗 4 张费用」，逐张再印 4 行就是噪音。
这与 D-263（洗回卡组不逐张印）是同一个判断。

## 4. 两次真实的红（都是既有用例抓到的）

### 4.1 开关放下面 → #122 回归

```
Error: 日志框下方仍留 29px 空白（占位块还在？）
Expected: <= 2 / Received: 28.5
```

`polish.spec.ts` 的 #122 用例守的是「日志列下方不留空块」（当年删掉聊天占位留下的洞）。
第一版把「细节」开关放在日志框**下方**，直接把日志框顶起来 —— 洞又回来了。
**修法：开关移到日志框上方。**

这条红说明分区放置不是审美问题：战报列的高度分配已经被用例固定住了。

### 4.2 断言只认 rgb → NaN

```
Error: 抽屉底板必须完全不透明（牌桌文字不得透上来）
Expected: 1 / Received: NaN
```

Tailwind v4 的计算样式是 `oklch()`，`/rgba?\(/` 匹配不到。
解析器补了 `oklch(L C H / A)` 分支 —— 这条与 D-156「颜色不能假设是 rgb」是同一个坑。
