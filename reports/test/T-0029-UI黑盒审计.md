## 3. 结论

**有条件发布。**

功能链路**没有一处阻断**：建房 → 换牌 → 六阶段 → 出牌 → 战斗 → 结算，桌面与移动都能走完，双端状态一致。问题集中在**「信息被遮住」和「手指点不准」**两类，不影响判定，但会让玩家卡住或误操作。

发布条件（建议先修这三条）：

1. **UI-01（#113）** 移动端手牌末张被裁且无法滑动 —— 后手起手 6 张就中招，属于「玩不了」级。
2. **UI-02（#114）** 顶栏提示条压住回合计时 —— 计时是这两个阶段的唯一时间信号。
3. **UI-03（#115）** 移动端卡组编辑 ± 按钮 24×20px —— 手指点不中，改一套卡组要几十次点按。

其余为体验级，可排期。

## 4. 缺陷清单

### P1 · 建议发布前修

#### UI-01 · 移动端手牌最后一张被裁切，且没有横向滚动（issue #113）

| 项 | 内容 |
| --- | --- |
| 位置 | 对战桌 · 手牌区（390×844） |
| 复现 | 390×844 → 人机对战 → 准备 → 换牌阶段（后手 6 张起手） |
| 现象 | 第 6 张卡右侧约 23px 落在视口外，卡名/费用可见、力伤与右侧边框被切；手牌区 `clientWidth 372 / scrollWidth 404`，`overflow-x: visible` —— **既无滚动条也不能滑动** |
| 证据 | `reports/ui/shots/23-mulligan-mobile.png`、`24-table-mobile.png`、`25-mobile-card-selected.png` |
| 黑盒影响 | 后手玩家**开局第一眼就看不全手牌**。他不知道自己有第 6 张、那张牌多少费；选中它才被"顶"进可见区，等于"要先猜着点一下才能看见"。抽牌后 8 张会更糟。这是本批唯一「直接影响能不能正常决策」的问题 |
| 建议 | 手牌容器改为横向可滚（含边缘渐隐/半张卡露出作为可滑提示），或按张数自适应卡宽（6 张时不小于 56px）；不要依赖选中后再滚动定位 |

#### UI-02 · 顶栏提示条遮挡回合计时（issue #114）

| 项 | 内容 |
| --- | --- |
| 位置 | 对战桌 · 顶栏中部（桌面 1440 与移动 390 均中） |
| 复现 | 人机房开局 → 观察顶栏「计时 Ns」；或推进到主要阶段前观察「请先点击卡组抽牌」 |
| 现象 | 提示条的盒子 `x 626~814, y 64~102`，计时「计时 116s」的盒子 `x 612~673, y 63~83`，**实测重叠**（见截图：只剩「计」字露在外面）。**常驻时间实测约 4 秒后移除**（`t+3.0s` 仍在、`t+4.1s` 已无）；「请先点击卡组抽牌」在抽牌完成后约 1 秒移除，但它在**重置阶段**就会提前出现。移动端更严重：整行被挤成「开 局 / 阶段 换 / 牌」，右侧「除外区『炎刃』0」也被压掉 |
| 证据 | `05-mulligan-selected-desktop.png`、`15-placing-desktop.png`、`23-mulligan-mobile.png` |
| 黑盒影响 | 换牌和充能这两个阶段，玩家唯一能判断"还剩多久"的就是这个数字。被盖住之后只剩提示条里那句「剩余 118 秒」兜底 —— 而那句在移动端排在第二行、字号更小。玩家会以为计时坏了（这正是 issue #99 修过一次的同类问题，换了个位置复发）。**注意这与 #94（D-262）记录的「开局 toast 遮挡」是同一处**：当时判为「约 3 秒消失、不影响操作」的观感项；本条的差异是**它盖住的恰好是计时本身**，且移动端不是「压住」而是「整行折行」 |
| 建议 | 提示条改为**不占顶栏行**（放到阶段条下方独占一行），或固定右对齐避开计时区；移动端把「除外区」这类次要信息折叠进日志 |

#### UI-03 · 移动端卡组编辑的加减按钮只有 24×20px（issue #115）

| 项 | 内容 |
| --- | --- |
| 位置 | 卡组编辑 · 「已选」与「待选」两个列表 |
| 复现 | 390×844 → 编辑卡组 |
| 现象 | 每行高 20px；`−` 24×20，`＋` 28×20，两者水平间距 3px；搜索框高 30px |
| 证据 | `49-deck-editor-mobile.png` |
| 黑盒影响 | 触控目标低于 44px 的一半以下。手机上改卡组时，`−` 与 `＋` 之间只有 3px，**点错方向是常态**；点错了又没有撤销提示，只能反向再点一次。玩家的体感是"卡组编辑做不了"，而不是"按钮小" |
| 建议 | 列表整体加高到 ≥44px 行高（或移动端切卡片式布局）；`−/＋` 各自 ≥40×40 并拉开间距；搜索框 ≥40px |

### P2 · 明显影响体验，建议排期

#### UI-04 · 1366×768 下首页「编辑卡组」完全在首屏外（issue #116）

| 项 | 内容 |
| --- | --- |
| 复现 | 1366×768 打开首页，不滚动 |
| 现象 | 页面内容高 932px；「编辑卡组」按钮 `top 834 / bottom 884`，**整块在 768 视口之外**，需滚动 164px |
| 证据 | `46-home-1366x768.png`（1440×900 下可见，但仍溢出 32px） |
| 黑盒影响 | 1366×768 是最常见的笔记本分辨率之一。第一次进来的玩家看不到"编辑卡组"，会以为这游戏只能用三套预设卡组 —— 而卡组编辑是 Demo 的卖点之一 |

| 项 | 内容 |
| --- | --- |
| 复现 | 清空 `localStorage['fc.introSeen']` → 首次进对战桌（此时停在换牌阶段） |

#### UI-07 · 战斗阶段攻击目标高亮过弱（issue #119）

| 项 | 内容 |
| --- | --- |
| 复现 | 主要阶段出随从 → 战斗阶段 → 点我方随从 |
| 现象 | 我方随从变为黄绿描边（明显）；可攻击的对方随从**只是描边颜色微调**，与常态差别很小；没有「可攻击」标记、没有指针变化、没有连线 |
