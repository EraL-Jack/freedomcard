# T-0027 · 法术卡拖拽落点验收（D-272 / issue #108）

- **日期**：2026-10-21
- **对象**：`client/src/selectors.ts`（新增 `dragDropIntent`）、`client/src/TableScreen.tsx`
  （`onDragUp`、法术区 `dropKey`、按牌型高亮）
- **依据**：issue #108、ADR-0061（落点判断纯函数化）、ADR-0049（出牌两段式）、ADR-0002（弱客户端）
- **基线**：`master` 上 D-271 之后（`64e5457`）

## 1. 结论

**可发布。**

法术与设置法术现在可以**拖到我方法术区直接出牌**（等价于点「出牌」）；
拖到随从格也不再报「只有随从需要指定位置」，而是按无位置出牌。
随从拖拽（上场 / 攻击）与费用区充能的行为未变。

## 2. 缺陷复现（修复前）

| 操作 | 期望 | 实际 |
| --- | --- | --- |
| 拖法术卡 → 我方法术区 | 出牌 | 无任何反应（法术区没有 `data-drop`，松手即取消） |
| 拖法术卡 → 随从格 | 出牌（法术无位置） | 提示「只有随从需要指定位置」，牌留在手里 |
| 拖随从卡 → 随从格 | 出牌 | 正常（唯一可用路径） |

## 3. 改动清单

| # | 改动 | 位置 |
| --- | --- | --- |
| 1 | 新增纯函数 `dragDropIntent()`：四类落点 → `play` / `charge` / `attack` / `none` | `selectors.ts` |
| 2 | `onDragUp` 只负责取 DOM 标记，判断交给纯函数 | `TableScreen.tsx` |
| 3 | 我方法术区注册 `dropKey="spell"`，拖法术时高亮 | 同上 |
| 4 | 落点是随从格但牌不是随从 → 无位置出牌（不传非法 `slot`） | 同上 |
| 5 | 高亮按牌型分（随从 → 随从区 / 充能阶段的费用区；法术 → 法术区） | 同上 |

## 4. 验证

### 4.1 单测（440 → 447，client 50 → 57）

| 用例 | 断言 |
| --- | --- |
| 法术 → 法术区 | `{ kind: 'play' }`（不带 slot） |
| 设置法术 → 法术区 | `{ kind: 'play' }` |
| 法术 / 设置法术 → 随从格（带 slot） | `{ kind: 'play' }` —— 忽略格子号 |

### 4.2 E2E（51 → 52）

`drag.spec.ts`「拖拽法术卡到法术区 = 出牌（issue #108）」：后攻方充能 → 推进到主要阶段 →
挑一张付得起的法术拖到我方法术区 → 手牌 −1、法术区或弃牌区增加、不出现
「只有随从需要指定位置」。

**红绿第二层**：临时注释掉法术区的 `dropKey="spell"` → 该用例红在
「手牌数没减 1」（10s 轮询超时）；还原即绿（16.7s 通过）。单跑 `drag.spec.ts` 3/3（1.1m）。
