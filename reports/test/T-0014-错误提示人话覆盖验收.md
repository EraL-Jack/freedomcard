## 1. 结论

Era 2026-10-13 定的「错误信息必须人话」这条，在房间层有一半没落实：

| 问题 | 具体 |
| --- | --- |
| 键名写错 | 客户端映射表把 `ROOM_NOT_FOUND` 写成 `NOT_FOUND` —— 这个映射**永远命中不了** |
| 缺 5 个码 | `GRACE_EXPIRED` / `NOT_HOST` / `NO_NEXT_GAME` / `INVALID_DECK` / `DECK_LOCKED` |
| 绕过映射 | 「开始下一局 / 离开 / 准备」三条通知直接拼 `${res.error}` |

判定**可发布**：纯文案与归属调整，不动协议与状态。

## 2. 为什么以前没暴露

服务端绝大多数失败分支都带中文 `message`，而 `failText` 优先用 `message`。
所以只有「某条路径只回错误码」时才露馅 —— 而这恰好是最难人工测到的分支（例如非房主点「开始下一局」）。

## 3. 改动

| 位置 | 改动 |
| --- | --- |
| `shared/src/constants.ts` | 新增 `ROOM_ERROR_TEXT`，类型 `Record<RoomErrorCode, string>` |
| `shared/src/index.ts` | 导出（**忘了 re-export 会让客户端拿到 `undefined` 而静默失效**，这是本项目踩过的坑） |
| `client/src/useRoom.ts` | 删本地表；`failText` 用共享表；三条通知统一 `failText` |
| `server/src/schema.test.ts` | 新增「每个码都有中文文案，且不是码本身」 |

## 4. 类型强制 vs 运行时测试

- **编译期**：`Record<RoomErrorCode, string>` 保证「新增错误码必须有文案」，漏写直接编译失败。
- **运行期**：测试再保证文案不是空串、也不是把码抄一遍（`ROOM_FULL` → `ROOM_FULL` 这种）。

两者都要：类型管「有没有」，测试管「是不是人话」。
