## 1. 结论

`replay.json` 此前**不可重放**：只有 Intent 序列、事件与哈希链，没有 seed / 卡组 / 指挥官。
它只能用来「对照哈希」，谁也没法从零重建那一局 —— 与「结论必须可复现」这条约定直接冲突。

现在记录里带上了开局装配，**用文件自身就能重建开局状态并逐帧比对哈希**。

判定**可发布**：只影响回放文件格式，不动协议、规则与对局行为。

## 2. 缺什么（改前）

| 字段 | 改前 | 作用 |
| --- | --- | --- |
| `intents` | ✅ | 操作序列 |
| `events` | ✅ | 每步产出的事件 |
| `hashChain` | ✅ | 每步结算后的哈希 |
| `seed` | ❌ | 没有它，洗牌与掷骰无法复现 |
| `decks` / `commanders` | ❌ | 没有它们，初始状态都建不出来 |

`hashChain[0]` 是「第一手之后」的哈希，改前连第一手的**起点**都无法复原。

## 3. 改动

| 文件 | 改动 |
| --- | --- |
| `room/session.ts` | 抽出 `seedSetup(opts): SeedSetup`；`seedGameState` 改为 `createInitialState(seedSetup(opts))` |
| `room/replay.ts` | `ReplayRecord` 加 `setup` / `initialHash`；新增 `markStart(setup, hash)` |
| `index.ts` | 开局处先 `seedSetup` → 建状态 → `markStart(setup, stateHash(state))` |

关键点：**建状态与记装配共用一份参数**。若两处各算一遍，出现「记录里的卡组与真正发出的牌不一致」时
几乎无法察觉。

## 4. 断言钉住的三件事

| 断言 | 意义 |
| --- | --- |
| `createInitialState(seedSetup(o))` 与 `seedGameState(o)` 深度相等、哈希一致 | 装配参数确实足以重建 |
| 自建卡组只改 `setup.decks[seat]`，`setup.commanders` 与默认完全一致 | 与 D-141「指挥官由阵营决定」不冲突 |
| `markStart` 后 `finish()` 产出里有 `setup` / `initialHash`；用 `setup` 重建的哈希 = `initialHash` | 「可复现」在文件层面成立 |
