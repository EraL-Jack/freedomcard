## 3. 为什么必须改形态，不是补内容

`return <GameOverPanel/>` 这一句把整棵牌桌树换掉了。它的代价不是「少一块界面」，
而是**在最需要上下文的那一秒把上下文删掉**：

- 战报没了 → `[data-testid="log"]` 取不到；
- 回放入口从 D-183 起置灰（公网流量）→ 战报是**唯一**复盘手段；
- 结算页零数据 → 「输了不知道为什么输」。

所以修法是「保留牌桌 + 叠加说明」。ADR-0074 把这条上升为通用规则：
**任何结束态界面都用覆盖层，不替换主视图。**

## 4. 红绿证据

| 层 | 取证方式 | 反证结果 |

| 战报 DOM | 直接跑新用例（旧实现） | `Expected: 1 / Received: 0`（14 次采样均为 0） |
| 遮罩避让 | **注入**：临时删掉 `sm:right-40 md:right-56`，让遮罩全屏 | `Expected: "log" / Received: "absolute inset-0 bg-slate-950/72"` |
| 终局 actionability | **注入**：把守卫改成 `if (false && …)` | 3 条单测全红；恢复后 35/35 绿 |
| 收起 / 展开 | 结构断言（`result-card` 计数 0 → 重新可见） | 由 D-308-d 的实现直接决定，旧实现无这些锚点 |

**为什么第二条要注入取证**：旧实现里战报压根不存在，「战报没被遮罩压住」这条断言
没有被测对象 —— 不注入就等于一条永远绿的空断言。这正是 ADR-0071 第 ④ 条的场景。

## 6. 过程中的环境事故（ADR-0075 的来源）

第一次跑全量出现 3 红：`determinism` / `turn.spec:116` / `drag.spec:88`。

按「先问红的是谁」做对照 —— **把三个文件退回旧实现再跑：`determinism` 与 `turn` 照样红，
`drag` 反而绿**。继续查环境，发现：

- `3000` 端口上还跑着另一个工作树（`Worktrees\Fcardgame\master-*`）的 server；
- `5173` 无人监听，vite 已漂到 `5177 / 5178 / 5180 / 5181` 四个孤儿实例；
- 长跑 vite 持续打 `ws proxy error: ECONNRESET` / `write ECONNABORTED`。

客户端收不到 socket 事件、服务端照常计时推进 → 失败快照里写着「第 3 回合 · 对手回合」，
而用例只走到第 1 回合的抽牌。清成单实例重启后 **72 条一次全绿**。

**这条要记住：全量 E2E 的数字只有在干净单实例环境下才可引用。**
跑之前查三件事：`3000`/`5173` 各只有一个 LISTENING PID、`/health` 200、PID 属于本次启动。
