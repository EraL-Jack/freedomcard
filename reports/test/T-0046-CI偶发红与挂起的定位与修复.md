# T-0046 · CI 偶发红与 6 小时挂起的定位与修复（D-316）

- 日期：2026-10-23
- 范围：`.github/workflows/ci.yml`、`client/playwright.config.ts`、`client/e2e/helpers.ts`
- 基线：`master = fe3617f`（D-315 收口；这正是被挂起 6 小时的那次 PR 的合并点）
- 结论：**可发布**（工作流的行为验收以本分支的 CI run 为准，见 §6）

---

## 1. 现象（从远端取，不靠印象）

最近 7 个 PR 的 check-runs：

| PR | typecheck / lint / test | 端到端（Chromium） | 耗时 |
| --- | --- | --- | --- |
| #169 | success | **cancelled** | 361 min |
| #168 | success | success | 7 min |
| #167 | success | **failure** | 10 min |
| #166 | success | success | 7 min |
| #165 | success | success | 17 min |
| #163 | success | success | 9 min |
| #162 | success | success | 13 min |

另外 `push master` 的两条也是红：`7eea2cc`（D-312 合并点）、`7dcc387`（D-313 合并点）。
**注意 #166 自己的 PR run 是绿的、它的 master push run 是红的** —— 同一份代码两种结果，
这本身就是「偶发」的强证据。

## 2. 两个根因

### 2.1 #169：`apt-get update` 无超时 → 挂 6 小时

`job 119840629901` 的日志最后两行：

```
13:03:51 Installing dependencies...
13:04:28 Ign:2 http://azure.archive.ubuntu.com/ubuntu noble InRelease
（此后 6 小时零输出）
19:04:15 ##[error]The operation was canceled.
```

annotation 写着 `The job has exceeded the maximum execution time of 6h0m0s`。
即：`playwright install --with-deps` → `sudo apt-get update` 卡在镜像上，而 **apt 自身没有超时**，
一直等到 GitHub 的 360 分钟 job 上限。与代码无关。

### 2.2 #167 / master 两次：充能按钮在点击落地前消失

`job 119815033355` 的失败段落：

```
✘ 77 zone-inspect.spec.ts:18 › D-265 堆叠区点开走浮窗，牌桌上不铺卡 (1.5m)
  Test timeout of 90000ms exceeded.
  Error: locator.click: Test ended.
  - waiting for getByTestId('charge')
    - locator resolved to <button ...>充能</button>
    - attempting click action
    - waiting for element to be visible, enabled and stable
    - element is not stable
    - retrying click action
    ...
    - element was detached from the DOM, retrying
  at helpers.ts:269
```

`master 7eea2cc` 的失败是同一行的另一种姿势（30s 用例超时，只有 detached 没有 not stable）。
两次都落在 `helpers.ts` 的同一行 —— **同一个 helper、同一个按钮**。

代码事实（`TableScreen.tsx:2438-2450`）：`charge` 按钮只在 `picked === c.uid` 时渲染，
`onClick` 里先 `session.charge([uid])` 再 `setPicked(null)` —— 按钮随即从 DOM 移除。
Playwright 的默认 click 超时是「整条用例的超时」，于是一次未落地就把 30s / 90s 全吃掉。

## 3. 改法

| ID | 位置 | 改动 |
| --- | --- | --- |
| D-316-a | `ci.yml` | `quality` 加 `timeout-minutes: 15`；`e2e` 加 `timeout-minutes: 30` |
| D-316-b | `ci.yml` | 「安装 Chromium」改成 `timeout --kill-after=30 300 … × 3 次`，步骤 `timeout-minutes: 15`，三次失败 `::error::` 退出 |
| D-316-c | `ci.yml` | 失败上传 `test-results` + 截图（`e2e-failure`，保留 14 天）；通过时才传 `e2e-screenshots` |
| D-316-d | `playwright.config.ts` | `trace: process.env.CI ? 'retain-on-failure' : 'off'`、`screenshot` 同理 |
| D-316-e | `e2e/helpers.ts` | 充能点击抽出 `chargeOne()`：单次点击 5s 上限、最多 3 次、**以费用区张数判是否落地**；新增 `tableSnapshot()` |

`chargeOne()` 的幂等性：点了之后事件还在播放队列里时，费用区张数不会立刻变。
所以重试前先 `expect.poll(费用区) > before`（5s 窗口）—— 涨了就是上一次其实点到了，
直接返回，**不会重复充能**（重复充能会破坏「留一张随从」的约定）。

## 4. 红绿验证（注入法，不靠连跑碰运气）

注入探针（已删除）：选中后 40ms 自动 `setPicked(null)`，模拟「按钮在点击落地前消失」。
**同一探针下换 helper**：

| 组合 | 结果 |
| --- | --- |
| 旧 helper + 探针 | **红** —— `element was detached from the DOM, retrying` at `helpers.ts:269`，与 CI 报错一字不差 |
| 新 helper + 探针 | **绿** —— `2 passed (33.6s)`（`turn.spec:37` + `zone-inspect:18`） |
| 新 helper + 无探针 | **绿** —— 同上 2 条 |

探针删除后 `grep -rn "TEMP-PROBE" app/` 无结果。

## 6. 工作流的验收方式

工作流没有本地执行器，`.github/workflows/ci.yml` 只能由 GitHub 真正跑一遍才算验过。
本分支的 PR run 同时验证三件事：

1. 新加的 `timeout-minutes` 与重试脚本语法正确（YAML 错会直接不出作业）；
2. 正常路径仍然是绿（安装 Chromium 一次成功、E2E 84 条通过）；
3. 失败上传步骤不干扰成功路径（`if: failure()` / `if: success()` 分支）。

## 7. 遗留

- **孤儿 vite 进程**：2026-10-13 留下三个（PID 17872 / 22244 / 12244，占 5178/5180/5181），
  本会话 `taskkill` 与 `Stop-Process` 均返回「拒绝访问」（属另一会话或更高权限启动）。
  不影响 CI 与生产 3100，但会占着 `node_modules/.vite`，必要时在管理员 shell 里清。
- `chargeOne()` 是兜底而非「修好竞态」。若该 helper 仍偶发红，应按 ADR-0081 §后果 的顺序
  转去查应用层（例如选中态被意外清掉），而不是继续加大重试。
