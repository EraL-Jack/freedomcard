# T-0023 · 回合边界指引验收（D-268 / issue #101）

- **日期**：2026-10-21
- **对象**：`client/src/useRoom.ts`（`turnPending`）、`client/src/selectors.ts`（`turnGuidance`）、
  `client/src/TableScreen.tsx`（提示条与顶栏归属）
- **依据**：issue #101、ADR-0057、ADR-0054（界面判定放纯函数）、ADR-0002（弱客户端）
- **基线**：`master` 上 D-267 之后（`dcb8c3b`）

## 1. 结论

**可发布。**

issue #101 报的现象（「充能阶段的提示在切换回合之前显示了」）已消除：交棒期间顶栏显示
**「回合切换中…」**，且**不给**「该你做什么」的提示；`turn:changed` 落地后才恢复
「你的回合 / 对手回合」与对应阶段指引。引擎、协议、回放格式均未改动。

## 2. 根因（不是引擎错，是消费端把中间帧当真）

回合边界在事件流里是两条（`core/src/rules/phase.ts`）：

```ts
events.push(phaseChanged(at, state.phase, 'charge'));   // 进入下一回合的充能
events.push(turnChanged(at, nextTurn, nextSeat));       // 才换席位
```

客户端为动画**逐条 reduce + 按相位停顿**（`FX_MS['phase:changed'] = 750ms`），于是两条之间存在一帧：

| `phase` | `activeSeat` | 界面读出的指引 |
| --- | --- | --- |
| `charge` | **还是我** | 「你的回合 · 充能阶段：点手牌里的随从 →『充能』放进费用区」 |

这一帧的局面（我的回合 + 我的充能阶段）**在我的回合里早已过去**，它只是播放时序的产物。
750ms 后 `turn:changed` 才应用，界面才改成「对手回合」—— Era 看到的就是这一段。

同类线索其实早在 `e2e/helpers.ts` 的 `activePage` 注释里记过（开局事件未播完时「短暂以为轮到我」），
当时只在测试侧绕开了，产品侧没修。

## 5. 过程中的一次自摆乌龙（记入 CHANGELOG）

E2E 首版的不变量写成「任何一帧都不得同时出现『你的回合』与『充能阶段』」——
**绿代码也红**，因为我方回合开头的充能阶段本来就长这样，这是合法组合。
改成「定位『阶段离开充能后又回到充能』的那一帧」再断言，才真正对准了 bug。

教训：**不变量必须先验证它在正确实现下恒真**，否则测的是措辞而不是行为。

## 6. 未覆盖 / 风险

- **观感未做真机确认**：「回合切换中…」持续约 0.75~2.5 秒（取决于从哪个阶段结束回合），
  交棒动画期间桌面会「安静」一点。这是 ADR-0057 的代价项，已记 README §10 第 24 条。
  若 Era 觉得这段时间空白太久，可选「保留上一次的指引直到交棒完成」—— 但那是另一种口径
  （会短暂显示已经过期的提示），需要他定。
- 本项**不涉及**服务端，生产 3100 无需重启（D-183 勘误：静态产物按请求读盘）。
