# T-0024 · 每局牌序相同的根因验收（D-269 / issue #103）

- **日期**：2026-10-21
- **对象**：`core/src/state.ts`（`createInitialState` 的初始游标）、`core/src/rng.ts`
  （新增 `initialRngCursor`）、`server/src/room/session.ts`（回放记录游标）、
  `server/src/tools/replay-verify.ts`（历史文件兼容）
- **依据**：issue #103、ADR-0010（种子随机）、ADR-0021（`GAME_SEED` 边界）、
  ADR-0058（派生入口唯一 + 记进回放）
- **基线**：`master` 上 D-268 之后（`65f1b51`）

## 1. 结论

**可发布。**

Era 报的「每次进游戏都是固定起手」已消除：不同局的牌序、先后手、起手各不相同，
同一种子仍完全可复现（回放链路未受影响）。引擎规则、协议字段、客户端界面均未改动 ——
这次修的是一条**从未接上**的线。

## 2. 根因

`createInitialState` 把随机游标写死成 `0`：

```ts
return {
  rngCursor: 0,          // ← 恒为 0
  seed: opts.seed,       // ← 只存进 state 供记录，一次都没参与随机
```

`startRule` 的洗牌、掷骰、发牌都从 `state.rngCursor` 出发，所以每局：

| 受影响 | 表现 |
| --- | --- |
| 洗牌 | 同一副牌序 |
| 掷骰定先后手 | 同一方永远先攻 |
| 起手发牌 | 同样的手牌 |

种子本身是好的 —— `nextSeed()` 每局都取 `Date.now()`，问题在它没有被使用。

### 为什么既有测试没拦住

| 测试 | 它断言什么 | 为什么漏 |
| --- | --- | --- |
| `rng.test.ts` | 同游标同结果、不同游标不同结果 | 从不问「游标的初值从哪来」 |
| `session.test.ts` 的 `nextSeed` 组 | 未设 `GAME_SEED` 时每次取时间（「防恒返回常量」） | 只测上游产量，不测它流到哪里 |

两处各自正确，中间接头无人看守 —— 属于「两处都对的契约拼起来会漏」的又一例
（与 D-181 的席位回收同类）。

```

       × 不同种子洗出的整副牌序也不同
```

## 4. 已知代价

- `InitialStateOptions` 多一个可选 `rngCursor`，仅回放重建会传（注释已写明）。
- 历史回放的 `initialHash` 与「用 seed 重新派生」的结果天然不同 —— 那些局当时确实用游标 0。
