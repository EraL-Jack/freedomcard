# T-0025 · 统领Ⅰ 5 档破坏的目标范围验收（D-270 / issue #105）

- **日期**：2026-10-21
- **对象**：`core/src/effects/blade-lord.ts`（`targetCandidates` 的 5 档分支）、
  `client/src/selectors.ts`（新增 `choiceSideLabels`）、`client/src/TableScreen.tsx`（浮层标注与按钮文案）
- **依据**：issue #105、ADR-0023（效果系统）、ADR-0059（极性分治）、H22（2026-10-21 修订）
- **基线**：`master` 上 D-269 之后（`e262a1f`）

## 1. 结论

**可发布。**

5 档「破坏一个力量值 ≤ 除外区炎刃数的随从」的候选集从**只列己方**改为**己方 + 对手**，
按「先己方、后对手」的顺序给出；选中对手随从时卡牌进对手弃牌区（按目标持有者搬卡）。
3/7/9 三个增益档位维持限己方，行为未变。

## 2. 缺陷复现（修复前）

| 条件 | 期望 | 实际 |
| --- | --- | --- |
| 除外区 5 张炎刃、己方 1 随从、对手 1 随从（力量 4） | 目标列表含对手那张 | 目标列表只有 `['b1']` |

证据：`effects.test.ts` 旧断言本身就是「候选只有己方」，测试与产品一起错 ——
H22（2026-10-19）把四档共用的「选择一个随从」统一限成己方，5 档因此不可用。
这是**夹具钉死缺陷**的又一例（同 D-269 的 `pipeline.test.ts`）。

## 4. 验证

### 4.1 单测（432 → 436，全绿）

| 用例 | 断言 |
| --- | --- |
| `effects.test.ts`「5 档…候选含对手场上」 | `options = ['b1','fb1']`；力量 6 的对手随从 `fb2` 不出现 |
| 同上（结算） | 破坏 `fb1` 后：`p2.board = ['fb2']`、`p2.graveyard = ['fb1']`、`p1.board` 不变 |
| `effects.test.ts`「5 档…也能破坏己方」 | 选中 `b1` → 己方随从进己方弃牌区，对手不受影响 |
| `selectors.test.ts`「候选跨双方才标注」 | `{ mine1: '我方', foe1: '敌方' }` |
| `selectors.test.ts`「单边候选不标注」 | 己方两项 → `{}`；冻结类只有对手一项 → `{}` |
| `selectors.test.ts`「子效果档位不参与」 | `options: ['l1','l3']` → `{}` |

红绿验证：只写测试不修实现 → 1 条红（`expected [ 'b1' ] to deeply equal [ 'b1', 'fb1' ]`），
修 `targetCandidates` 即绿。

### 4.3 未覆盖与理由

- **未加 E2E**：跑到 5 档要求除外区累计 5 张炎刃，得先在 E2E 里打完整条除外链
  （骑士 / 老兵 / 焚典逐个发动），用例又长又脆；该分支是纯候选集计算，单测可精确覆盖。
- **人机局未受影响**：`core/src/ai.ts` 从不发动指挥官技能，`pendingChoice` 分支只处理被动触发的
  展示类选择，因此不会出现「AI 破坏自家随从」。
- **力量门槛吃卡面值**：带临时 +1 力量的随从仍按卡面值比较。这是 1 档召唤、号令的既有口径，
  本次未改（若 Era 要按修正后力量比较，需另开一条）。

## 5. 风险与边界

| 风险 | 说明 |
| --- | --- |
| 目标列表变长 | 双方铺满时 5 档最多 12 项，浮层已 `max-h-64` 可滚动 |
| 误点自家随从 | 两步确认（先选档位、再选目标）+「我方 / 敌方」标注 |
| 与冻结类口径混淆 | 冻结 / 审判等显式「敌方随从」效果不因本条放宽（ADR-0059 §4） |
