### 2.1 新增 E2E 覆盖的链路

| 步骤 | 断言 |
| --- | --- |
| host 点「认输」 | 按钮变红、文案变「确认认输（本局判负）」，本局**未**结束 |

## 3. 关键设计点

1. **认输 ≠ 离开**：认输只发 `concede` Intent → 单局 `game:ended` → BO3 记分后 `awaitingNext`；
   离开走 `forfeitSeries`，直接写 `seriesWinner`。两者在 UI 上必须能区分，否则 BO3 没法只输一局。
2. **两段式确认**：认输不可撤销，第一次点击只改外观，第二次才发 Intent。
3. **起手张数作为先手判据**：不依赖「谁先手」的随机结果，先手 5 / 后手 6（docs/16 §1.2），
   与第 1 局谁先手无关，测试稳定。

## 4. 未覆盖 / 已知限制

1. **认输没有撤销**：两段式只防误触，不提供反悔（如需反悔要新增「取消」语义，属规则决策）。
2. **认输按钮在待定选择浮层期间**：浮层会盖住底部按钮，此时只能通过「放弃」退出该选择；
   是否需要「浮层内也能认输」未定。
3. **移动端触控**：两段式按钮在窄屏上的点击区域未真机验证。
