## 4. 回放粒度实测（验收 6）

临时 spec 连打两局（`_rematch-replay.spec.ts`，取证后已删）：

```
新增回放： [
  { "file": "eea1b60a-…-1792666095249.json", "intents": 3, "rounds": 0 },
  { "file": "eea1b60a-…-1792666101336.json", "intents": 7, "rounds": 0 }
]
```

- 同一个房间 id、两个时间戳 → **两份独立文件**；
- `rounds: 0` → 不是 BO3 式的多局归档（那会把第 2 局塞进同一份的 `rounds`）。

## 6. 事故记录：生产进程被误杀

清理开发残留进程时把**生产 3100 的 worker** 一并停掉了（`tsx src/index.ts` 与
`tsx watch` 的命令行太像，靠 PID 判断时选错）。发现方式：后台任务报 `failed` +
`netstat` 里 3100 不再 LISTENING。已立即重启并验证：`3100=200`、公网 3/3。

**教训（已写进本轮记忆）**：清理进程要按**端口属主**（`netstat` → PID → 命令行）
逐条确认，不要按「路径里含 Fcardgame 的 node 进程」批量杀 —— 生产进程与 dev 进程
路径完全一样，只有启动参数不同（`SERVE_STATIC=1 PORT=3100`）。
