## 2. 本轮体验目标

> 由执行方预填，供用户对照感受。**本轮只有骨架，没有玩法** —— 目标只看工程链路，不看游戏性。

1. 一条命令能把服务端与客户端同时跑起来，页面显示「服务端已连接」。
2. 手机连同一 WiFi 能打开页面（局域网联机测的前置条件）。
3. 375（手机竖屏）与 1440（电脑全屏）两档下页面不溢出、不遮挡。
4. 明确知道当前**什么还没有**（房间、对战、规则引擎），且工程里没有偷偷预置任何玩法。

## 3. 建议的体验步骤（可直接照做）

### 3.1 电脑端

```bash
cd app
pnpm install     # 期望 exit=0
pnpm dev         # 同时起 server(3000) 与 client(5173)
```

1. 浏览器打开 <http://localhost:5173> —— 页面应显示连接状态（已连接 / 未连接）。
2. 另开标签访问 <http://localhost:3000/health> —— 应返回 `{"ok":true,"version":"0.1.0"}`。
3. 缩放浏览器窗口到约 **375px 宽**与**全屏（1440+）**各看一眼，记录是否有溢出、按钮过小、文字被截。

### 3.2 手机端（同 WiFi）

```bash
pnpm --filter @app/client run dev   # vite 已开 host: true
```

4. 手机浏览器访问 `http://192.168.31.153:5173`（本机实测 IP；若 IP 变了用 `ipconfig` 查）。
   ⚠️ Windows 网络配置文件为 **Public** 时默认拦截入站，打不开多半是防火墙，需放行 5173 / 3000 端口。

### 3.3 生产形态（可选）

```bash
pnpm build
cd packages/server && SERVE_STATIC=1 pnpm start
```

5. 访问 <http://localhost:3000> —— 应由服务端直接托管页面（不再是 Vite）。

### 3.4 对照「什么还没有」

6. 看 `app/packages/core/src/engine.ts`：`applyIntent` / `reduce` 是 `TODO(slot)` —— 这是**正确的**，规则等你输入后才写。
   如果你在任何文件里看到具体的卡牌名、费用、血量、攻击等**玩法内容**，那是违规，请立刻记进第 4 节。
